# Test case: insert a spawn row (precondition for smoke-3)

Maps to Subtask 2.3 acceptance criteria: paired case A. Inserts a row into
the `spawns` table. The next case (smoke-3) asserts that the DB-reset
fixture wiped this row between cases.

## Setup

The per-case DB-reset fixture has run; `~/.agent-director/state.db` is
fresh and contains the current-schema tables with zero rows.

## Steps

1. Confirm `sqlite3` is on PATH inside the container.
2. Confirm `~/.agent-director/state.db` exists and its `PRAGMA
   user_version` matches the current schema version. The expected value is
   **derived from the shipped binary**, not hard-coded: a throwaway
   reference DB is created with `agent-director list --store-path <tmp>` and
   its `user_version` is read back, so an intentional schema bump moves both
   the fixture DB and the reference in lockstep and this case keeps passing.
3. Insert one row into `spawns` with a known `claude_instance_id`
   (`smoke-leftover`).
4. Confirm exactly one row is now in `spawns`.

## Pass criteria

`COUNT(*)` from `spawns` returns `1` after the insert; exit 0.

```bash
set -euo pipefail
DB="$HOME/.agent-director/state.db"
test -r "$DB"

# Derive the expected schema version from the shipped binary rather than
# hard-coding a literal (the source constant internal/store/store.go
# `schemaVersion` is not copied into the container). Create a throwaway
# reference DB with the same binary and read its user_version back; the
# next intentional schema bump moves both DBs in lockstep, so this case
# does not silently re-break.
ref_db=$(mktemp -u)
agent-director list --store-path "$ref_db" >/dev/null
expected_version=$(sqlite3 "$ref_db" 'PRAGMA user_version')
rm -f "$ref_db" "${ref_db}-wal" "${ref_db}-shm"
test "$expected_version" -gt 0  # guard: a vacuous 0=0 pass means the fixture stopped stamping user_version

version=$(sqlite3 "$DB" 'PRAGMA user_version')
test "$version" = "$expected_version"
echo "smoke-2: schema version $version matches binary-derived $expected_version"

# --- isolation-fixture assertion (the reason this case exists) ---
sqlite3 "$DB" "INSERT INTO spawns (claude_instance_id, state, cwd, tmux_session_name, relay_mode) VALUES ('smoke-leftover', 'running', '/tmp', 'cd-smoke-2', 'passthrough');"
count=$(sqlite3 "$DB" 'SELECT COUNT(*) FROM spawns;')
test "$count" = "1"
echo "smoke-2 ok: 1 row in spawns (leftover for smoke-3 to detect)"
```
