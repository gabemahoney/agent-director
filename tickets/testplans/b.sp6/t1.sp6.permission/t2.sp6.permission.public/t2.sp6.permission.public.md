# All agents expose durable permission stuck through independent reads

Maps to the all-agent public display and process-to-process continuation of
`stuck` / `permission_unanswered` (PRD t1.ob8.s4).

## Setup

The DB-reset fixture gives a fresh store at the binary's current schema. The
driver writes `[state] settle_ms = 0` and
`permission_unanswered_timeout_seconds = 30` to `config.toml`, loads the
expected wire fields from `/work/source/cmd/agent-director/testdata/stuck/permission.json`,
and records the case start time. All SQL uses `/opt/driver/sql.sh`; no prior
case or wall-clock delay supplies evidence.

## Steps

1. For each of `claude`, `codex` and `cursor`, insert a `check_permission`
   spawn `public-<agent>` (relay on, session `ts-public-<agent>`, launch token
   `1111111111111111`, `permission_epoch` 7) and one request with the
   fixture's token and tool, owned by that launch and epoch, with
   `fallback_at` 2020-01-01 and basis `deadline`.
2. Confirm `spawns.stuck_observation` is still empty, so only a read can
   commit the episode.
3. Run `agent-director status --instance-id public-<agent>` until
   `spawns.stuck_version` moves, at most 5 reads at the same state. It must
   move by exactly 1.
4. Run `status`, then `get` (a fresh process), for the same id. Read
   `stuck_version` again.
5. Run `agent-director list --state stuck --limit 3`.

## Pass criteria

- Every `status` and `get` row has the fixture's `state`, `stuck_reason`,
  `request_token` and `tool_name`, `tmux_session_name` `ts-public-<agent>`,
  no `unchanged_minutes`, and a `since` in the fixture's exact
  millisecond-UTC format whose time is at or after the case start (the
  committing read, not the 2020 fallback clock).
- `get.since` equals `status.since`; `get.permission_requests` and
  `get.unproven_requests` each hold 1 request.
- `stuck_version` is unchanged by the repeated `status` and `get`; the raw
  `spawns.state` is still `check_permission`.
- `list` returns exactly the 3 ids, each with the fixture's `state` and
  `stuck_reason` and none of `since`, `request_token`, `tool_name` or
  `unchanged_minutes`.
- The evidence line shows the token prefix, tool, list size, each agent's
  `stuck_version` and, in place of any run-time timestamp, the facts asserted
  about each agent's `since` (`>=start,get=status`: at or after the case
  start, and equal across `status` and `get`), so every passing run prints
  the same line.
