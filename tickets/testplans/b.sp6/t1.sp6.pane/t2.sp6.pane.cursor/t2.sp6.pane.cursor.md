# Cursor reports idle_screen unavailable and is never sampled, while its permission request still shows needs_intelligence

Maps to Epic t1.sp6.rk acceptance 3 and Epic t1.sp6.6s acceptance 1, 2 and
10: every row carries `idle_screen_availability`, Cursor's is `unavailable`
and its quiet row stays in its ordinary state, and a Cursor permission request
still shows `needs_intelligence` with one
`ad.spawn.displayed_state_transition` record.

## Setup

The DB-reset fixture gives a fresh store at the binary's current schema. The
driver writes `[state] settle_ms = 0`, `idle_screen_timeout_seconds = 60`,
`needs_intelligence_timeout_seconds = 30` and the Codex stand-in as
`[launch] codex_path`. All SQL uses `/opt/driver/sql.sh`.

## Steps

1. Insert a `working` Cursor row `cursor-quiet` with a 1-second override and
   a committed pane baseline unchanged since 2020-01-01 in its current
   permission epoch; run `status` and `get`.
2. Insert a `check_permission` Cursor row `cursor-asks` and one request with
   the shared `needs_intelligence.json` fixture's token and tool, owned by its
   launch and epoch, its fallback clock started 2020-01-01; run `status` until
   it commits (exactly 1).
3. Insert an `ended` Codex row `codex-ended`; run `list`.
4. Read the trail's records for `cursor-asks` and `cursor-quiet`.

## Pass criteria

- Step 1: `status` shows `working` and `idle_screen_availability`
  `unavailable` with exactly the keys `context`, `family_state`,
  `idle_screen_availability` and `state`; `get` shows the same, no `since` or
  `unchanged_minutes` and no `stuck_reason` member. The row's
  `observation_version`, `display_observation` and baseline are unchanged (it
  was never sampled).
- Step 2: `status` shows the fixture's `state` (`needs_intelligence`),
  `request_token` and `tool_name`, availability `unavailable`, with exactly
  the keys `context`, `family_state`, `idle_screen_availability`,
  `request_token`, `since`, `state`, `tmux_session_name` and `tool_name`.
- Step 3: every listed row carries its availability: `codex-ended`
  `available`, both Cursor rows `unavailable`.
- Step 4: exactly one `ad.spawn.displayed_state_transition` record for
  `cursor-asks`, with exactly the keys `event`, `instance_id`, `new_state`,
  `prior_state` and `ts`: `check_permission` to `needs_intelligence`, `ts`
  equal to step 2's `since`; none for `cursor-quiet`.
- The trail holds no `ad.spawn.stuck_transition` record, and no
  `ad.spawn.state_transition` record names `idle_screen` or
  `needs_intelligence`.
