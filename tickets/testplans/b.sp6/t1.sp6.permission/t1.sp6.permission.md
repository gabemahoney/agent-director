# permission-stuck

Shell testplan for the permission-unanswered `stuck` display. The driver resets
a binary-derived store before each independent case. No credentials,
interactive agent or background worker is needed, and no wall-clock wait
supplies evidence: each case seeds a request whose fallback clock started long
before the timeout, and the shipped binary does every observation. The only
wait is `guards`' bounded retry of its zero-wait `decide` while that refuses
`ErrStoreBusy` under load (every 100 ms, at most 10 s).

The cases cover, through public reads and refusals only, all-agent display with
process-to-process continuation, representative continuity and report-only
command guards. Expected wire values come from the shared
`cmd/agent-director/testdata/stuck/permission.json`. Exact clock boundaries,
stale races and settlement matrices stay unit tests. Each case prints one
compact JSON evidence line of observed values, with each `since` printed as
the facts asserted about it rather than its run-time timestamp, so every
passing run prints the same line (a case on a binary without the schema
prints `availability: unavailable` and exits 77, never a pass). The
runnable driver is `test/driver/permission-stuck.cjs`.
