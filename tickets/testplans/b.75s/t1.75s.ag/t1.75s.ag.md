# Epic 13 (b.ssz) — `epic-13-agents` testplan

t1 collector for agent-generic spawning (Plan Bee `b.ssz`, Epic `t1.9r1.js`,
Task `t2.9r1.js.zo`; SRD `t1.ssz.pm` SR-14.4 Docker harness row, SR-14.5).
Each t2 is a plain-English case the Docker harness executes under
`make test-docker EPIC=epic-13-agents` with `DRIVER_MODE=shell`. Cases
`agent-1` to `agent-7` pin the agent input and `claude_path`; `agent-8` to
`agent-10` (Epic 4, Task `t2.9r1.u5.xm`) pin the Codex launch;
`agent-11` to `agent-17` (Epic 4, Task `t2.9r1.u5.i4`) pin a Codex row's
life: its first prompt, hook states, end and every verb; `agent-18` to
`agent-21` (Epic 4, Task `t2.9r1.u5.39`) pin the permission relay on a
Codex row. Epic 5 of the plan extends this testplan further.

## Driver mode

Every refused call carries `PATH=/opt/driver/stand-in-claude:$PATH`, so a
regression that launched would start the stand-in, not Claude Code. Every
refusal case checks that nothing was written: `agent-director list` and
`/opt/driver/sql.sh` show no row, `tmux ls` shows no new session, and the
templates directory holds only what the case itself wrote. A refused call
ends with exit 1 and a JSON envelope on stderr whose `err_name` and
`err_description` the case checks.

The Codex cases (`agent-8` to `agent-10`) name the Codex stand-in
`/opt/driver/stand-in-codex/codex` in `[launch] codex_path`. It records
its argv, environment, cwd and pid in `/tmp/stand-in-codex/<instance id>/`
and writes nothing else, so a case reads the launch from there and a
refused call is proved by the record directory never appearing. The
Codex folder a case gives through `--extra-env CODEX_HOME=<folder>` is
compared with `/opt/driver/tree-snapshot.sh` before and after, and
`~/.codex` must never exist.

The life-cycle cases (`agent-11` to `agent-17`) type hooks into the
stand-in's pane with `/opt/driver/pane-hook.sh --agent codex` (small inline
Codex payloads whose `transcript_path` is a rollout under a temporary
`CODEX_HOME`), and shorten the pending grace through
`[tmux] pending_grace_seconds` where they wait for `unreported` (30 s is
the load-time minimum). Typing `/exit` at the stand-in's pane makes it fire
a Codex `SessionEnd` (reason `other`) through `agent-director hook --agent
codex` and exit, as Codex does; it does nothing on a signal, so `kill`
sends no end report. `agent-12` puts the forking launcher
`/opt/driver/forking-codex/codex` on the PATH (`codex_path` unset): it runs
the stand-in as a child, so the hook's parent is not the row's pane process.

The relay cases (`agent-18` to `agent-21`) spawn with `--relay-mode on` and
type a Codex `PermissionRequest` with `pane-hook.sh --agent codex --no-wait`,
which blocks on the relay; `decide` or the case's other moves answer it, and
`pane-hook.sh --wait` reads the hook's stdout. The stand-in's bash drops a
lone Escape (the Escape pane answer of `agent-21`), so the hook line typed
after it keeps its first letter. Typing a Codex `Interrupt` (no `agent_id`)
is how a case ends the hold on plain `send-keys`.

## Cases

| case | what it pins |
|---|---|
| `agent-1` | no agent on the call and none in the template: `ErrAgentMissing` |
| `agent-2` | an agent that is not exactly `claude` or `codex` (`gemini`, `Claude`): `ErrAgentInvalid` |
| `agent-3` | `make-template` with `agent_args` and no agent: `ErrTemplateAgentMissing`, no file |
| `agent-4` | `agent_args` of one agent inherited by a spawn of the other: `ErrAgentArgsMismatch` |
| `agent-5` | a codex spawn with allow, deny or ask (call or template): `ErrPermissionsUnsupported` |
| `agent-6` | `make-template --agent codex` with allow, deny or ask: `ErrPermissionsUnsupported`, no file |
| `agent-7` | `[launch] claude_path` launches the stand-in with `claude` off the PATH; `get` shows `agent` `claude` |
| `agent-8` | a codex spawn whose `agent_args` hold a subcommand, `-c hooks.*`, `--remote`, `--disable hooks` or a question-tool form (with `disable_ask_user` on): `ErrSpawnDeniedFlag`, nothing written |
| `agent-9` | a codex spawn through `codex_path` with `relay_mode` on: `pre_trust` `ok`, a `pending` codex row, and the recorded argv holds `--no-daemon`, the eight `hook --agent codex` entries, their trust state, the paste setting and the folder trust before any `--` |
| `agent-10` | a codex spawn leaves the `CODEX_HOME` folder tree unchanged; with `CODEX_HOME` unset no `~/.codex` is created and no Claude file is written |
| `agent-11` | a codex spawn through `codex_path` with no first prompt: the row stays `pending` inside the shortened grace, then `find-missing` notes `liveness_note` `unreported` (not listed) |
| `agent-12` | a forking launcher on the PATH (`codex_path` unset): the SessionStart is ignored as `pid_mismatch` with one `ad.hook.pane_is_grandparent` naming codex; the row stays `pending`, then is noted `unreported` |
| `agent-13` | hooks typed with `pane-hook.sh --agent codex`: SessionStart `waiting` (agent `codex`, the payload's session id and rollout path), UserPromptSubmit `working`, Stop `waiting`, UserPromptSubmit `working`, Interrupt `waiting` |
| `agent-14` | `pause` on a codex row succeeds; the row is `ended` with the end report set; the trail holds the row's find-missing tick with `proc_absent` and `new_state` `ended` |
| `agent-15` | `resume` of the paused row gives `pending`; the stand-in's argv holds `resume <session id>`; a SessionStart with source `resume` and the same id gives `waiting`, session id kept |
| `agent-16` | `find-missing`: a row that exited by `/exit` typed outside `pause` stays `waiting` until the run makes it `ended` (not in `ids`); a row whose process ended with no end report becomes `missing` (in `ids`) |
| `agent-17` | the temporary `CODEX_HOME` tree (paths, modes, bytes) is identical before spawn and after spawn, pause, resume, kill, find-missing and expire |
| `agent-18` | relay on: a Codex `PermissionRequest` for `Bash` gives `check_permission` and an open request with Codex's `tool_name` and `tool_input` (no `tool_use_id`, no `agent_id`); `decide --decision allow` puts the allow envelope on the hook's stdout; plain `send-keys` is `ErrDialogMaybeOpen` until a Codex `Interrupt` is typed (`turn_end`), then types |
| `agent-19` | `decide --decision deny`: the deny envelope with the stored reason `operator` on the hook's stdout; the request reads `deny`, `operator`, `delivered` |
| `agent-20` | `[relay] timeout_seconds` 5 and no `decide`: the deny envelope after 2 to 5 s, `decision_reason` `timeout`; Codex's `PermissionRequest` entry carries the same window (`--timeout 5`, `timeout=5`) |
| `agent-21` | the relay hook is killed (`fallen_back`); `send-keys --request-token --as deny --key Escape --expect-pane-sha256` answers it (`sent`, `pane`); plain `send-keys` still `ErrDialogMaybeOpen`; a typed Codex `Interrupt` gives `waiting` and `turn_end`, then plain `send-keys` types |
