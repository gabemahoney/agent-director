# Test case: Persistence failures never publish a successful terminal row

Maps to E1 AC3/5/7; SR-4.1, SR-4.2, SR-9.1 and Task2 t3.jf1.3e.d6.k2.

## Setup

The Docker driver reset provides a clean baseline. Source the shared Cursor collector helper from the exact revision source mount. It creates a new protected HOME, explicitly routed store, short private tmux namespace, unique id and synthetic Node ACP peer using the existing cursorfix/runtime.js. No Cursor login or real AD store is accessed. Requires Linux, Node, Bun, tmux, jq and procfs.

## Steps

1. Launch to waiting and install an isolated id-scoped failure of the ended SQL write.
2. Pause and require ErrPauseTimeout despite proved runtime death and bound retirement.
3. Require the row was never ended, remove the injected trigger and reconcile to missing.

Each predicate is exact in the executable block. These actions use the shipped CLI, real tmux and a synthetic protocol peer.

## Pass criteria

Every shell/JSON/SQL assertion in the block passes, followed by the one deterministic evidence JSON object with this case id and authenticated_cursor=false. This does not satisfy the separate authenticated operator acceptance. Record the exact source/binary SHA and Node/Bun/tmux/kernel versions in the scheduler receipt.

```bash
set -euo pipefail
source /work/source/test/driver/cursor-owned-launch.sh
```
