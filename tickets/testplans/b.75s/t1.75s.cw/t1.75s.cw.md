# Busy send E2 (b.kii) — `busy-send-claude-wait-turn` testplan

t1 collector for a covered Claude Code agent's Wait Turn delivery through its
own hooks (Idea `b.kii`, Plan `b.xis`, Task `t2.xis.oo.u8`, Subtask
`t3.xis.oo.u8.sm`; SRD `t1.kii.kn` SR-3.1, SR-3.3 to SR-3.5, SR-5.6). Its one
case runs under `make test-docker EPIC=busy-send-claude-wait-turn` with
`DRIVER_MODE=shell`, against the real CLI, store, tmux and hook processes.

## Driver mode

The agent is the Claude stand-in `/opt/driver/stand-in-claude/claude`: an
interactive bash that is the row's pane process. The case plays Claude Code's
part: it types each hook with `/opt/driver/pane-hook.sh --stderr-pipe`, so
every hook is a direct child of the recorded pane process with a pipe for its
stderr, as Claude Code gives it (the wake writes only to a stream that takes
a write deadline, which a regular file does not), and it runs the owned
`FileChanged` hook itself where Claude Code would after a change of the
watched path. It makes no claim about Claude Code's own intake, watcher or
wrapping, which stay with the Managing Intelligence's qualification.

Claude is not in this release's covered set, so the case records the row's
Launch and conversation covered, with route A at the Launch's own wake
endpoint, through `/work/source/bin/ts-helper seed-busy-send-claude-route`
(the canonical `apitest` seeds). The Go tests own the refusal, output-boundary
and settings matrices; this case checks the real hook transport end to end.
