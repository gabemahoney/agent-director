# smoke-5: DB-reset ends every tmux server, whatever its sessions are named

Pins the fix for `b.8yq`: the per-case `db-reset.sh` used to kill only
sessions named `cd-*`, and only on the default socket. A spawn's default
session name is `<cwd base>-<id8>` and cases name their own sessions
freely, so an earlier case's processes (a real Claude Code among them) kept
running into later cases and rewrote `~/.claude.json` under them
(spawn-9's flake). The reset now ends every tmux server whose socket is in
a `tmux-<uid>` directory under `/tmp`, `$HOME` or `TMUX_TMPDIR`, gives its
panes' processes a grace of 5 to 6 s to exit, and kills what is still
running.

Because it ends every tmux server of its user, the reset runs only in the
harness container: the image (test/Dockerfile) sets
`AGENT_DIRECTOR_TEST_HARNESS=1`, and without exactly that value the reset
exits 2 and changes nothing.

## Setup

Per-case DB-reset has run. The case starts four tmux servers of its own,
none of whose sessions is named `cd-*`:

- the default server (`/tmp/tmux-<uid>/default`);
- a `-L smoke5` server (`/tmp/tmux-<uid>/smoke5`);
- a server under a per-case `TMUX_TMPDIR` made with `mktemp -d` (under
  `/tmp`);
- a server under a per-case `TMUX_TMPDIR` in `$HOME` (`$HOME/smoke5-tmux`,
  as ze.us uses `$HOME/tmuxsock-tmpl5`). Its pane ignores SIGHUP and
  SIGTERM and starts a child `sleep` that inherits that, so it outlives
  its server's end: only the reset's kill ends it.

The reset is run the way the driver runs it, `bash /opt/driver/db-reset.sh`,
from a shell outside tmux and without the case's `TMUX_TMPDIR`.

## Steps

1. Start the four servers; wait until the stuck pane has written its pid
   and its child's pid.
2. Record every server pid and pane pid, and the stuck pane's child pid.
3. Insert a `spawns` row (as smoke-2 does) so the store's re-creation is
   visible.
4. Check the case's environment has `AGENT_DIRECTOR_TEST_HARNESS=1`. Run
   the reset once without it (`env -u AGENT_DIRECTOR_TEST_HARNESS`). The
   other values it refuses (empty, `0`, `true`) are covered by the unit
   test `TestDBResetRefusesOutsideTheHarness`
   (test/driver-scripts/db_reset_test.go).
5. Run `bash /opt/driver/db-reset.sh`, timing it and keeping its stderr.
6. Check the outcome (pass criteria). An EXIT trap ends whatever the case
   started that is still there and removes its temp dirs.

## Pass criteria

- `AGENT_DIRECTOR_TEST_HARNESS` is `1` in the case's environment.
- The reset without it exits 2, prints nothing on stdout, and prints on
  stderr `db-reset: refusing to run outside the Docker test harness
  container` and `Nothing was changed.`. After it, every recorded pid is
  still running, every server answers `list-sessions`, and `spawns` still
  has its 1 row.
- The reset with it exits 0, in at least 5000 ms (the stuck pane's grace)
  and under 9000 ms (the grace of at most 6 s, then the kill).
- No recorded pid is still running (a zombie counts as gone).
- No tmux server answers `list-sessions` on any of the four sockets.
- The reset's stderr names the stuck pane: `tmux pane <pid> still running`.
- `~/.agent-director/state.db` exists and `spawns` has 0 rows.

Every failed check exits through `fail`, which prints what it found.

```bash
set -euo pipefail
fail() { echo "FAIL: $*"; exit 1; }
work="$(mktemp -d)"
tmp_sock_dir="$(mktemp -d)"
home_sock_dir="$HOME/smoke5-tmux"
mkdir -p "$home_sock_dir"
socks=()
stuck_pid=""
cleanup() {
    for s in "${socks[@]}"; do tmux -S "$s" kill-server 2>/dev/null || true; done
    [ -z "$stuck_pid" ] || pkill -KILL -s "$stuck_pid" 2>/dev/null || true
    rm -rf "$work" "$tmp_sock_dir" "$home_sock_dir"
}
trap cleanup EXIT

# new_server <session> <pane command> <tmux command...>: starts a server with
# one session through the given tmux command and records its socket.
new_server() {
    local sess="$1" cmd="$2" sock
    shift 2
    "$@" new-session -d -s "$sess" "$cmd" || fail "new-session $sess via [$*] failed"
    sock="$("$@" display-message -p -t "$sess" '#{socket_path}')" || fail "no socket_path for $sess via [$*]"
    socks+=("$sock")
}

# still_running prints each recorded pid still running (a zombie counts as
# gone) with its command line, one per line.
still_running() {
    local pid st
    for pid in "${pids[@]}"; do
        st="$(sed -E 's/^.*\) //' "/proc/$pid/stat" 2>/dev/null | cut -d' ' -f1 || true)"
        if [ -n "$st" ] && [ "$st" != Z ]; then
            echo "$pid[$(tr '\0' ' ' < "/proc/$pid/cmdline" 2>/dev/null || true)]"
        fi
    done
}

# 1. Four servers, no cd-* session among them. The last pane ignores SIGHUP and
#    SIGTERM, and so does its child sleep.
stuck_cmd="trap '' HUP TERM; sleep 300 & echo \"\$\$ \$!\" > '$work/stuck'; wait"
new_server smoke5-default 'sleep 300' tmux
new_server smoke5-named 'sleep 300' tmux -L smoke5
new_server smoke5-tmp 'sleep 300' env TMUX_TMPDIR="$tmp_sock_dir" tmux
new_server smoke5-home "$stuck_cmd" env TMUX_TMPDIR="$home_sock_dir" tmux
for _ in $(seq 50); do
    [ -s "$work/stuck" ] && break
    sleep 0.1
done
read -r stuck_pid stuck_child < "$work/stuck" 2>/dev/null \
    || fail "the stuck pane never wrote its pids to $work/stuck"

# 2. Every server pid and pane pid, and the stuck pane's child.
pids=("$stuck_child")
for s in "${socks[@]}"; do
    panes="$(tmux -S "$s" list-panes -a -F '#{pid} #{pane_pid}')" || fail "list-panes on $s failed"
    read -r -a found <<<"$panes"
    [ "${#found[@]}" -eq 2 ] || fail "list-panes on $s gave [$panes]; want one server pid and one pane pid"
    pids+=("${found[@]}")
done

# 3. A row the store's re-creation must drop.
DB="$HOME/.agent-director/state.db"
/opt/driver/sql.sh "$DB" "INSERT INTO spawns (claude_instance_id, state, cwd, tmux_session_name, relay_mode) VALUES ('smoke5-leftover', 'running', '/tmp', 'smoke5-default', 'passthrough');"

# 4. The image marks the harness; without that mark the reset refuses and
#    changes nothing. (Empty, 0 and true are refused too:
#    TestDBResetRefusesOutsideTheHarness.)
[ "${AGENT_DIRECTOR_TEST_HARNESS:-}" = 1 ] \
    || fail "AGENT_DIRECTOR_TEST_HARNESS is [${AGENT_DIRECTOR_TEST_HARNESS:-}]; want 1 (test/Dockerfile sets it)"
rc=0
env -u AGENT_DIRECTOR_TEST_HARNESS bash /opt/driver/db-reset.sh >"$work/refuse.out" 2>"$work/refuse.err" || rc=$?
[ "$rc" -eq 2 ] || fail "db-reset without the marker exited $rc; want 2; stderr: $(cat "$work/refuse.err")"
[ ! -s "$work/refuse.out" ] || fail "db-reset without the marker printed on stdout: $(cat "$work/refuse.out")"
for want in 'db-reset: refusing to run outside the Docker test harness container' 'Nothing was changed.'; do
    grep -qF "$want" "$work/refuse.err" \
        || fail "db-reset without the marker: stderr lacks [$want]: $(cat "$work/refuse.err")"
done
alive="$(still_running | wc -l)"
[ "$alive" -eq "${#pids[@]}" ] \
    || fail "only $alive of ${#pids[@]} recorded pids still running after the refused reset: $(still_running | tr '\n' ' ')"
for s in "${socks[@]}"; do
    tmux -S "$s" list-sessions >/dev/null 2>&1 || fail "no tmux server answers on $s after the refused reset"
done
count="$(/opt/driver/sql.sh "$DB" 'SELECT COUNT(*) FROM spawns;')"
[ "$count" = "1" ] || fail "spawns has $count row(s) after the refused reset; want 1 (store untouched)"

# 5. The reset, as the driver runs it.
t0="$(date +%s%N)"
rc=0
bash /opt/driver/db-reset.sh 2>"$work/reset.err" || rc=$?
elapsed_ms=$(( ($(date +%s%N) - t0) / 1000000 ))
[ "$rc" -eq 0 ] || fail "db-reset exited $rc; stderr: $(cat "$work/reset.err")"

# 6. Nothing left running, no server answering, the stuck pane killed by the
#    reset in time, and a fresh store.
left="$(still_running)"
[ -z "$left" ] || fail "still running after the reset: $(echo "$left" | tr '\n' ' ')reset stderr: $(cat "$work/reset.err")"
for s in "${socks[@]}"; do
    if tmux -S "$s" list-sessions >/dev/null 2>&1; then
        fail "a tmux server still answers on $s: $(tmux -S "$s" list-sessions 2>&1)"
    fi
done
grep -qF "tmux pane ${stuck_pid} still running" "$work/reset.err" \
    || fail "the reset's stderr does not name the stuck pane ${stuck_pid}: $(cat "$work/reset.err")"
[ "$elapsed_ms" -ge 5000 ] || fail "the reset took ${elapsed_ms} ms; want at least 5000 (the stuck pane's 5 s grace)"
[ "$elapsed_ms" -lt 9000 ] || fail "the reset took ${elapsed_ms} ms; want under 9000 (a grace of at most 6 s, then the kill)"
test -r "$DB" || fail "no $DB after the reset"
count="$(/opt/driver/sql.sh "$DB" 'SELECT COUNT(*) FROM spawns;')"
[ "$count" = "0" ] || fail "spawns has $count row(s) after the reset; want 0 (store not re-created)"

echo "smoke-5 ok: the refused reset changed nothing; ${#socks[@]} servers ended, ${#pids[@]} pids gone, stuck pane ${stuck_pid} killed, reset took ${elapsed_ms} ms"
```
