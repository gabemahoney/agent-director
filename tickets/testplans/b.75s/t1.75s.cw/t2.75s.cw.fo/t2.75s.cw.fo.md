# busy-send-claude-wait-turn-5: forced delivery through the owned hooks

Maps to Epic `t1.xis.p8` acceptance criteria 1 to 5 (Task `t2.xis.p8.zp`,
Subtask `t3.xis.p8.zp.gi`; SRD `t1.kii.kn` SR-3.4, SR-3.5, SR-3.9, SR-4.1 to
SR-4.4, SR-8.4; E5 Main Agent decisions 1, 8 and 10). A force skips only the
waits for turn end and a Dialog. While its finite call runs, the call alone
touches the wake endpoint: once for its first frozen prompt, and once more for
each later prompt after the preceding prompt has both complete output and
AD's own exact `UserPromptSubmit` sighting: recorded order plus independent
force admission (Task `t2.xis.w3.ok`, SR-2.5 and SR-4.3).
Each touch lets the owned `FileChanged` hook, a real process in the
agent's pane, write that one prompt; a wake with no prompt to issue writes
nothing. Only the exact sighting admits a prompt; a force whose prompt is not
sighted when its call ends returns `pending`, and the agent's later sighting
makes it `handed_over`. AD types nothing and answers no Dialog.

Route obligations this case observes through the installed binary:

- **SR-3.9 and SR-4.2:** the keyless installed path: no tmux input,
  paste, input journal attempt or cancellation by AD; the permission
  request's fields never change, whatever the force does.
- **M1 ForceAdmissionSound:** admission only at the exact sighting. A force
  call's return, a repeated wake and the reads do not admit.
- **M2 P-C4.3:** each forced prompt's Messages are recorded issued and
  `forced` by the time its hook exits. The in-process order (intent before
  the first byte) is `TestClaudeForcedWake`'s.
- **M2 P-C4.4:** the real hook finishes a `pending` force.
- **Contributions:** the awaiting record that a withheld sighting leaves
  (`awaiting_turn_start` 1, then 0) contributes to P-C4.2, which E2 owns.
  Each forced output goes through a stderr pipe bounded by the force's
  recorded deadline, which contributes to P-C4.6, which E6 owns.

Outcome, reason, race and recovery matrices are Task `t2.xis.p8.y2`'s and
the Go hook tests'. This case checks the shipped wiring once.

It makes no claim about Claude Code's own watcher, intake, wrapping,
compaction, plan Dialog or timing. Those premises are checked by the Main
Agent's separately authorized SR-8.3 live qualification on the AD test VM,
which this case neither performs nor authorizes.

## Setup

Per-case DB-reset; `/opt/driver/busy-send-claude.sh cw5` (the collector's
"Driver mode"). A relay-on spawn of the stand-in Claude with a startup
prompt (`start-<tag>`), so SessionStart schedules no detached startup touch
and every touch of the endpoint after a rewind is the step's own. No
coverage, route, force or wake endpoint is seeded.

## Steps

1. Spawn; type `SessionStart`, then the startup prompt's `UserPromptSubmit`.
2. Send `f1` and `f2` (confirmed, about 6,000 bytes each, so they cannot
   share a 9,600-byte prompt). Type `FileChanged`. Type `Stop`; run no
   `FileChanged` for its hint, so both stay Held at the idle prompt.
3. Run `force-delivery` in the background. Wait on the endpoint's change
   events for the call's notification. Type `FileChanged`, then type it
   again.
4. Type the sighting of step 3's prompt. Wait on the endpoint's change
   events for the running call's next notification. Type `FileChanged`,
   then type it again. Type the sighting of this prompt. Join the call;
   `get-force` its `force_id`; `get`.
5. Send `g1` (confirmed). With `[relay] timeout_seconds = 2` configured,
   type a `PermissionRequest` (tool `Bash`), which records its request and
   falls back. Read the request's token once; `get-permission`.
6. Run `send-keys` of `g2` (confirmed) with `--force` in the background. Wait
   on the endpoint's change events for the call's notification. Type
   `FileChanged`; `get-permission`.
7. Type no sighting. Join the call; `get-force`; `get`; `get-permission`.
8. As the caller, press `Escape` in the agent's pane with tmux directly (then
   `C-c`, which only empties the stand-in shell's line). Type the sighting of
   step 6's prompt. `get-force`; `get`; `get-permission`.
9. Read the tmux call log, the input journal and the pane.

Before each step that waits for a touch, the case sets the endpoint's
modification time back to a fixed past second; a changed time is the touch.

## Pass criteria

- Steps 1-2: the Launch is a covered `spawn` Launch with route
  `claude_hooks` and its own wake endpoint (as case 1); `f1` is Held
  waiting `turn_running`, `f2` `earlier_message`; the ordinary wake exits 0
  and writes nothing; `Stop` touches the endpoint and the row is `waiting`.
- Step 3: the call touches the endpoint; the first wake exits 2, nothing on
  stdout, exactly `[agent-director: message 1 of 1]\n<f1>` on stderr; the
  second exits 0 and writes nothing.
- Step 4: the exact sighting secures the completed prompt's order and
  independently admits it, leaving the row `working`; the still-running call
  touches the endpoint with no `Stop` between; the wake exits 2 with exactly
  `[agent-director: message 1 of 1]\n<f2>`; the repeat exits 0 and writes
  nothing. `force-delivery` exits 0 with `force_result` `outcome`
  `handed_over`, `reason` `admitted`, `ended_at` set, `carried_pairs` `f1`
  then `f2` (the case's Caller UUID), and `carried_results` each
  `sent_unconfirmed`, Final, `handed_over_not_proven` (never
  `delivered_confirmed`), `forced` true. `get-force` returns `lookup`
  `found` and that same `force_result`. `get` shows `awaiting_turn_start` 0
  and `held_count` 0.
- Step 5: both completed forced prompts have been sighted and ordered, so
  in the existing turn `g1` is Held waiting `turn_running`; the relay hook
  exits 0 with nothing on stdout; the row is `check_permission`; the request reads
  `delivery` `fallen_back`, `decision` null, `pane_answer` `none`,
  `proven_gone_at` null.
- Step 6: the call touches the endpoint (the accepted `g2` gives no wake of
  its own before the force); the wake exits 2 with exactly
  `[agent-director: message 1 of 2]\n<g1>\n\n[agent-director: message 2 of 2]\n<g2>`;
  the row is still `check_permission`; the request reads exactly as in step
  5 (all fields but `hook_gone_at`).
- Step 7: `send-keys` exits 0 with `request_id` `g2` and `force_result`
  `outcome` `pending`, `reason` `awaiting_admission`, `ended_at` null,
  `carried_pairs` `g1` then `g2`, `carried_results` each `sent_unconfirmed`,
  Final, `handed_over_not_proven`, `forced` true. `get-force` returns
  `found` and that same `force_result`. `get` shows it as `delivery.force`
  (`pending`) with `awaiting_turn_start` 1. The request is unchanged.
- Step 8: `get-force` reads `handed_over`, `admitted`, `ended_at` set, with
  the same `force_id`, `started_at`, `carried_pairs` and `carried_results`;
  `get` shows `awaiting_turn_start` 0 and `held_count` 0. The request is
  still unchanged: AD recorded no decision and no pane answer.
- Step 9: no tmux call of agent-director's sent keys or a paste buffer (the
  case's own `Escape` and `C-c` are logged as the case shell's), the input
  journal is empty, and the pane shows none of the Messages' texts.

```bash
set -euo pipefail
. /opt/driver/busy-send-claude.sh cw5

f1="force-one-$tag-$(head -c 6000 /dev/zero | tr '\0' 'f')"
f2="force-two-$tag-$(head -c 6000 /dev/zero | tr '\0' 'g')"
g1="dialog-one-$tag"
g2="dialog-two-$tag: forced with its send"
# pairs NAME...: carried_pairs for the case's Caller UUID, in order.
pairs() { jq -cn --arg c "$caller" '[$ARGS.positional[] | {caller_uuid: $c, request_id: .}]' --args "$@"; }
# handed NAME...: carried_results' expected rows: each Final sent_unconfirmed, forced.
handed() { jq -cn '[$ARGS.positional[] | [., "sent_unconfirmed", true, "handed_over_not_proven", true]]' --args "$@"; }
results() { jq -c '[.carried_results[] | [.request_id, .class, .final, .reason, .forced]]' <<<"$1"; }
# readback FORCE: get-force reads FORCE's own force_result, found.
readback() {
    local got
    got="$(agent-director get-force --force-id "$(jq -r '.force_id' <<<"$1")")"
    [ "$(jq -cS '[.lookup, .force_result]' <<<"$got")" = "$(jq -cS '["found", .]' <<<"$1")" ] \
        || fail "get-force read [$got]; want found and the call's own [$1]"
}
perm() { agent-director get-permission --request-token "$token" | jq -cS 'del(.hook_gone_at)'; }

# Step 1: a relay-on production spawn with a startup prompt; its turn starts.
agent-director spawn --agent claude --cwd "$work" --instance-id "$id" --tmux-session-name "cd-cw5-$tag" \
    --relay-mode on -- "start-$tag" >/dev/null || fail "spawn exited non-zero"
launched spawn startup
quiet UserPromptSubmit "$(jq -cn --arg p "start-$tag" '{prompt: $p}')"

# Step 2: two Messages that cannot share a prompt wait out the turn; its end's
# hint is lost, so both stay Held at the idle prompt.
send f1 "$f1" turn_running
send f2 "$f2" earlier_message
quiet FileChanged "$changed"
rewind
quiet Stop "$stop"
touched || fail "Stop with Messages Held did not touch the wake endpoint"
[ "$(state)" = waiting ] || fail "row is [$(state)] after Stop; want waiting"

# Step 3: an idle force; its call's notification brings the forced wake, which
# writes the first frozen prompt alone; a callback before its sighting writes nothing.
rewind
start_call agent-director force-delivery --instance-id "$id"
await_touch "force-delivery"
wakes "$(printf '[agent-director: message 1 of 1]\n%s' "$f1")"
quiet FileChanged "$changed"

# Step 4: the exact sighting orders and admits the completed prompt and starts
# a turn; the still-running call's next notification, with no Stop between,
# brings a separate wake mid-turn for the
# second prompt; a repeated callback writes nothing; its sighting admits the force.
rewind
sighting
[ "$(state)" = working ] || fail "row is [$(state)] after f1's sighting; want working"
await_touch "the running force call's next notification"
wakes "$(printf '[agent-director: message 1 of 1]\n%s' "$f2")"
quiet FileChanged "$changed"
sighting
join_call
force="$(jq -c '.force_result' "$work/call.out")"
jq -e --argjson p "$(pairs f1 f2)" '.outcome == "handed_over" and .reason == "admitted" and .ended_at != null
    and .carried_pairs == $p' <<<"$force" >/dev/null || fail "force-delivery returned [$force]; want handed_over admitted carrying f1, f2"
[ "$(results "$force")" = "$(handed f1 f2)" ] || fail "force-delivery carried [$(results "$force")]; want $(handed f1 f2)"
readback "$force"
[ "$(delivery '.awaiting_turn_start, .held_count')" = "[0,0]" ] \
    || fail "after the force the delivery block reads $(delivery '.awaiting_turn_start, .held_count'); want 0 awaiting, 0 Held"

# Step 5: a Message sent mid-turn waits for it, as ever; a relayed
# PermissionRequest with no time left falls back, its Dialog open and undecided.
send g1 "$g1" turn_running
write_config $'[relay]\ntimeout_seconds = 2'
hook PermissionRequest '{"permission_mode":"default","tool_name":"Bash","tool_input":{"command":"touch x","description":"write a file"}}'
[ "$rc" -eq 0 ] && [ ! -s "$work/out" ] || fail "the relay hook exited $rc, stdout [$(cat "$work/out")]; want 0 and no answer"
token="$(/opt/driver/sql.sh -readonly "$db" "SELECT request_token FROM permission_requests WHERE instance_id = '$id' AND decision IS NULL;")"
[[ "$token" =~ ^[0-9a-f-]{36}$ ]] || fail "the relay hook recorded no open request: [$token]"
[ "$(state)" = check_permission ] || fail "row is [$(state)] with the request open; want check_permission"
request="$(perm)"
jq -e '.delivery == "fallen_back" and .decision == null and .pane_answer == "none" and .proven_gone_at == null' <<<"$request" >/dev/null \
    || fail "the request reads [$request]; want fallen_back, undecided, unanswered, not proven gone"

# Step 6: g2 sent with force; the force freezes g1 and g2, and its notification
# brings a forced wake through the open Dialog, which stays as it was.
rewind
start_call agent-director send-keys --instance-id "$id" --text "$g2" --confirmed-delivery \
    --caller-uuid "$caller" --delivery-request-id g2 --force
await_touch "send-keys --force"
wakes "$(printf '[agent-director: message 1 of 2]\n%s\n\n[agent-director: message 2 of 2]\n%s' "$g1" "$g2")"
[ "$(state)" = check_permission ] || fail "row is [$(state)] after the forced wake; want check_permission"
[ "$(perm)" = "$request" ] || fail "the forced wake changed the request: [$(perm)]; was [$request]"

# Step 7: with its sighting withheld, the call returns pending.
join_call
jq -e --argjson p "$(pairs g1 g2)" '.request_id == "g2" and (.force_result | .outcome == "pending"
    and .reason == "awaiting_admission" and .ended_at == null and .carried_pairs == $p)' "$work/call.out" >/dev/null \
    || fail "send-keys --force returned [$(cat "$work/call.out")]; want g2's force pending awaiting_admission carrying g1, g2"
force="$(jq -c '.force_result' "$work/call.out")"
[ "$(results "$force")" = "$(handed g1 g2)" ] || fail "the force carried [$(results "$force")]; want $(handed g1 g2)"
readback "$force"
[ "$(delivery '.force.force_id, .force.outcome, .awaiting_turn_start')" = "$(jq -c '[.force_id, "pending", 1]' <<<"$force")" ] \
    || fail "get's delivery reads $(delivery '.force.force_id, .force.outcome, .awaiting_turn_start'); want the force pending, 1 awaiting"
[ "$(perm)" = "$request" ] || fail "the call's return changed the request: [$(perm)]; was [$request]"

# Step 8: the caller answers the Dialog in the pane; the agent's later sighting
# of the forced prompt admits the pending force. AD answered nothing.
row="$(/opt/driver/sql.sh -readonly "$db" "SELECT IFNULL(tmux_socket,'') || '|' || pane_id FROM spawns WHERE instance_id = '$id';")"
sock="${row%%|*}"
tmux ${sock:+-S "$sock"} send-keys -t "${row#*|}" Escape
tmux ${sock:+-S "$sock"} send-keys -t "${row#*|}" C-c
sighting
got="$(agent-director get-force --force-id "$(jq -r '.force_id' <<<"$force")")"
jq -e --argjson b "$force" '.lookup == "found" and (.force_result | .outcome == "handed_over" and .reason == "admitted"
    and .ended_at != null and .force_id == $b.force_id and .started_at == $b.started_at
    and .carried_pairs == $b.carried_pairs and .carried_results == $b.carried_results)' <<<"$got" >/dev/null \
    || fail "after the later sighting get-force reads [$got]; want the same force handed_over admitted"
[ "$(delivery '.awaiting_turn_start, .held_count')" = "[0,0]" ] \
    || fail "after the later sighting the delivery block reads $(delivery '.awaiting_turn_start, .held_count'); want 0 awaiting, 0 Held"
[ "$(perm)" = "$request" ] || fail "the request changed: [$(perm)]; was [$request]"

# Step 9: agent-director typed nothing; the case's own keys are its shell's.
awk -F'\t' '$1 != "agent-director" && $2 ~ /(^| )send-keys -t [^ ]+ Escape $/' "$TMUX_CALL_LOG" | grep -q . \
    || fail "the case's direct Escape is not in the tmux call log"
no_product_input "force-one-$tag" "force-two-$tag" "dialog-one-$tag" "dialog-two-$tag"

echo "busy-send-claude-wait-turn-5 ok: idle force wrote f1 alone, the call's next notification after its sighting brought f2 mid-turn with no Stop, repeats wrote nothing, handed_over admitted and read back; send-keys --force through an open Dialog wrote g1 and g2, request unchanged; withheld sighting returned pending; the caller's own key and the later sighting made it handed_over; nothing typed or answered by agent-director"
```
