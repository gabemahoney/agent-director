# User Docs Best Practices

User docs are for the people who install and run agent-director, and for the programs and agents that call it. The README gets a user running in five minutes (rules: `readme-guide.md`). Every other user-facing fact lives in exactly one of the files below.

## Rules for every user doc

- Keep it short. State each fact once, in the file that owns it, and link to it from anywhere else.
- Current state only. No history, no "used to", no "since release X", no bug IDs. A minimum version a caller checks for is current state and may stay.
- No implementation detail: no source files, functions, packages, spec IDs (SR-x), design reasons or alternatives considered.
- No testing: how the project is tested belongs in `test-writing-guide.md`.
- Concrete, copy-pasteable commands. No code beyond commands, config files and sample output.
- Don't explain common tools (tmux, jq, sqlite3, cron) beyond the exact commands a step needs.
- Error names, fields and states are the contract; advice text is a hint.
- Stay generic: no one client's integration.
- Error cases and recovery go only in `caller-contract.md`, `operator-actions.md` and `maintenance.md`.

## The files

| File | Belongs | Doesn't belong |
|---|---|---|
| `README.md` | What agent-director is, prerequisites, the one-line install, a first spawn, scheduling the sweeps | Everything else |
| `docs/install.md` | Full requirements, every install path and `install.sh` flag, upgrading, the TypeScript client install, uninstall | Using agent-director |
| `docs/usage.md` | Day-to-day use past the first spawn: spawn states, session names, MCP use, the permission relay, templates, pause and resume | Every flag (that is `cli-reference.md`); error handling |
| `docs/configuration.md` | Every `config.toml` key: range, default, what it bounds, when a change takes effect | Why a default was chosen; measurements |
| `docs/maintenance.md` | Scheduling `find-missing` and `expire`; bringing sessions back after a reboot | Hand repair (that is `operator-actions.md`) |
| `docs/caller-contract.md` | Rules for programs and agents that call agent-director: what errors mean, when to retry, the live-row sequence | Steps only a human may take |
| `docs/operator-actions.md` | Human-only procedures: `agent-director-admin`, each refusal that needs a human, and the exact commands to check and fix it | Anything an automated caller may do |
| `docs/hooks.md`, `docs/permissions.md`, `docs/settings.md` | How a spawn's hooks, permissions and settings layer over Claude Code's or Codex's own | Claude Code's or Codex's own reference (link to it) |
| `docs/multi-account.md` | Running a spawn under another Claude or Codex account | General `extra_env` use |
| `pkg/api/README.md`, `pkg/ts-bun-client/README.md` | The Go and TypeScript client APIs | The CLI, install of the CLI |
| `docs/cli-reference.md`, `docs/mcp-reference.md`, `docs/admin-reference.md` | Generated by `make generate` from the verb descriptions | Hand edits: change the description and regenerate |

## Changing user docs

- Put a new fact in the one file whose "Belongs" column fits. If none fits, ask before creating a file, and add it to this table first.
- Before you rename or move a heading, find what points to it. Error text and verb descriptions name headings in `operator-actions.md` and `caller-contract.md`, and the `pkg/api/readme_*_test.go` tests pin their wording.
