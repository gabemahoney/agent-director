## Concrete actions inspected

- internal/cursorhost/requests.go admit establishes one request token, the immutable approval deadline (`timeout`), relay settlement (`settle`) and separate finite native lifetime. InsertCursorRequest atomically stores the received raw params, NULL hook/child identity and false main-turn eligibility, and raises check_permission under current independent runtime/pane authority.
- tick arbitrates a deliberate pane choice against API decisions with ClaimCursorPaneAnswer. It discards a captured relay choice before changing relay state at the approval deadline. It reads a settled first-writer verdict or writes timeout deny through AckCursorDecision. A failed or absent ack does not enqueue a response, including deny. Request settlement retires a queued response terminally; an unqueued unanswered request alone can become connected native fallback. cancel terminally retires every pending request.
- AckCursorDecision in internal/store/cursor_permission.go acquires the write transaction, checks current launch/life/runtime/session/connection plus independent kernel/pane evidence, rechecks deadlines after that evidence, and guards the exact persisted settlement. A first-writer allow past its approval deadline stays unacknowledged; timeout deny and ack are one transaction. Return to enqueue follows successful COMMIT. A stored decision alone has no relay write authority.
- enqueue selects the appropriate existing fixed deadline, removes that request's menu keys and queues one guarded serialized frame. The guard rejects terminal/retired requests and elapsed request deadlines, then calls CheckCursorAnswer. That store action again validates full authority and requires the exact row's durable relay ack or matching sent native claim, with no close/proof.
- protocol.writeLoop serializes actual pipe writes, checks authority before dispatch and again in the writer goroutine, rechecks transport expiry after potentially slow evidence and refuses a closed/failed transport. Queue admission/retirement is linearized by outputMu; failed/closed transports complete all accepted pending callbacks and never replay them. A guard rejection is a terminal request failure, not a physical-write completion event. A partial/short/uncertain write never establishes receipt or execution.
- execution requires the exact execute-kind tool_call_update, current session/tool correlation, completed/failed status and validated integer exitCode plus non-null stdout/stderr. ProveCursorToolRan preserves any earlier decision/reason/ack/claim, fills only missing proof fields and never promotes unknown origin to main. A previously acknowledged request can gain tool_ran proof/reason while pane_answer remains none; proof is not a fabricated native claim.

## Mapping and scope

| Concrete distinction / interleaving | Existing abstraction | What is and is not established |
|---|---|---|
| Atomic admission and held nonterminal writes | Hold36h transaction/lock actions, conditional working hold, fixcut proof; Hold36hCx rec/lock/prov | Existing state/hold design applies. Kernel/runtime/FD/pane validation is an implementation refinement obligation, tested independently; it is not a TLA process-identity theorem. |
| API first writer, relay ack versus response/exit | B146R5Cx HP/HA/HD/HE: poll, ack, timeout deny+ack, answer; dec/ack/got remain separate | HA/HD precede HE; enqueue and queue residence can stutter between them. This is not automatically proof of Cursor's physical output worker or native lifetime. Current raw-byte and failed/missing-ack tests challenge that refinement. |
| Ack followed by loss before the application receives an answer | Hold36hCx RelayGasp with LastGasp; B146R5Cx HDie from the acknowledged exit state where LastGasp is enabled | Already represented; do not invent a novel last-gasp model or infer receipt from ack. Hold36hCx KeysSafe preserves the unproven hold through that window. Historical B146R5Cx AckTrue and DecideTruthful are stronger receipt-style properties under their own environment assumptions; they are **not** Cursor's delivered contract under ack loss. No such property is newly claimed or silently renamed. |
| Queued allow/deny retirement, cancellation and post-guard expiry | HA/HD→HE versus loss/dead/no-answer actions provide an overapproximation for ack/no-answer outcomes; Hold36hCx separates ack from prov | A physical queue slot and Cursor's queued/retired/native flags are not explicit model variables. The model does not itself prove exact queue/native retirement. The concrete rule—no HE for a retired queued request, including deny—is discharged here by the actual production writer/controller tests and raw retained-pipe evidence, not a claimed model theorem. |
| Relay settlement with still-open native request | Hook loss/dialog availability versus a separate HumanKey/PaneAnswer action | A deliberate fresh native answer is a distinct action. Actual captured stale choices are discarded before fallback; queued/terminal requests lose menu authority. The abstract allowance of a human answer after some losses overapproximates the implementation; it does not authorize reviving a queued Cursor reply. PlainOK/KeysSafe depend on proof, not just relay settlement. |
| Unknown NULL child versus main eligibility | Hold36hCx CxUnknownOrigin, ChildID, Eligible and MainRec; CxIdentityProof is the negative control | Unknown-origin request is outside Main even with ChildID empty. Main/child lifecycle cannot manufacture exact execution proof. The existing NULL-safe/control contexts already distinguish the dangerous inference from NULL identity. Their historical expected outcomes remain unchanged. |
| Slow lock/evidence crosses approval/confirmation/transport deadline | B146R5Cx store lock, phase/deadline and bounded caller waits | Existing design separates decisions, lock waits, ack and exit. Millisecond exact bounds and the second physical writer guard are code-level obligations, covered by the actual gateway lock and queue tests and the established detailed controller matrices. |
| Outside/sent pane claim versus execution | Separate pane/prov/ack/dec facts; Hold36hCx step-2c PlainOK | A public claim alone cannot supply proof or Cursor ACP authority. Exact native option/token arbitration and output validation remain tested implementation obligations. |

The queue/native distinction is a **documented abstraction limit**, not automatically proved by B146R5Cx's separated ack/exit actions. Its concrete lost-authority traces collapse to existing no-answer/loss outcomes; fresh native choices are separate actions, and the existing hold abstraction already conservatively retains unproven requests. This Task introduces no new design behavior or demonstrated missing abstract interleaving that requires a model extension. Adding flags merely to force a TLC gate would violate the user's rule. There is therefore no model/configuration change. A future formal proof of the stronger physical queue/native refinement would need an explicitly scoped model extension and its own positive/control/probe design; this report does not invent that proof or its verdicts.
