# recov-3: find-missing is a no-op when every live row is alive

The negative case: real `spawn` produces two sessions whose pane
processes run, and `find-missing` transitions nothing. The image's
`claude` never reports in, so both rows are `pending` and, run seconds
after the spawn, still inside their grace period
(`pending_grace_seconds`, 60 s by default, measured from the launch
start): `find-missing` leaves them as they are and lists neither. Were
either judged, its recorded pane process still runs, so it would be
kept all the same.

## Setup

Per-case DB-reset.

## Steps

1. Spawn two Claudes.
2. `find-missing` → expect `count=0`, `.ids=[]`.
3. Inspect both rows: still in their original live states.

## Pass criteria

- find-missing exits 0 with `count=0`.
- Both rows' states are unchanged.

## Script

```bash
set -euo pipefail
id1=$(agent-director spawn --cwd /tmp | jq -r '.claude_instance_id')
id2=$(agent-director spawn --cwd /tmp | jq -r '.claude_instance_id')
test -n "$id1" && test -n "$id2"

res=$(agent-director find-missing)
count=$(printf '%s' "$res" | jq -r '.count')
ids=$(printf '%s' "$res" | jq -c '.ids')
if [ "$count" != "0" ] || [ "$ids" != "[]" ]; then
    echo "FAIL: count=$count ids=$ids; want 0/[]"; exit 1
fi

# Neither row should be missing.
for id in "$id1" "$id2"; do
    state=$(agent-director get --claude-instance-id "$id" | jq -r '.state')
    if [ "$state" = "missing" ]; then
        echo "FAIL: row $id wrongly marked missing"; exit 1
    fi
done
echo "recov-3 ok: find-missing left both live rows alone"
```
