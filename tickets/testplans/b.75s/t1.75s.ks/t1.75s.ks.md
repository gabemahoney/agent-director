# Epic 5 — `epic-05-stop` testplan

t1 collector for Epic 5 (`t1.8op.5f` — Stop live Spawns: kill + pause).
Each t2 is a plain-English case the Docker harness executes. The
Epic 5 Progression Contract requires every t2 to pass under
`make test-docker EPIC=epic-05-stop` per the orchestrator's first-hand
audit.

## Driver mode

All cases are written for `DRIVER_MODE=shell` — the orchestrator runs
the harness with `make test-docker EPIC=epic-05-stop`. Each t2 body
has a single fenced ` ```bash ` block the driver executes after the
per-case DB-reset fixture.

The kill and pause cases find a row's session only by its `@ad_owner`
label, never by name, so the cases that seed a row and make its session
by hand (kill-1, kill-4, kill-6's neighbour, kill-7, pause-3 and
pause-4) create
a `cat` session under
the harness's reserved `cd-*` prefix with `-e
AGENT_DIRECTOR_INSTANCE_ID=<row id>`, give the row a `launch_token` (16
lowercase hex) and label the session with the five-field
`ad1 <token read with sqlite3> <$N> <row id> <store id read with sqlite3
from store_meta>`, set with `set-option -t '<$N>'` (a four-field label
counts as no label, so such a case would silently test Gone). kill-1,
kill-4, pause-3 and pause-4 also set the agent pane's `@ad_pane`
`<token> <%N>`; their rows record no pane, so the verb adopts the pane
whose `@ad_pane` names the row's token (`kill` waits on its process;
`pause` types `/exit` into it by pane id and records it on the row).
pause-3 and pause-4 put an unlabelled decoy `cat` at window 0 pane 0
and split the agent's pane off it, so a send to `name:0.0` would land
in the decoy. The kill and pause cases check sessions by their session
id `$N` and pane content by pane id, never only by a name target (a
name target prefix-matches). kill-5 and kill-6 rows carry a launch token too, so
they cannot pass merely because a row with no token is never Ours.

kill-8, kill-9, kill-10 and kill-11 spawn X for real with
`PATH=/opt/driver/stand-in-claude:$PATH` prefixed to the
`agent-director` command (its pane process is an interactive bash that
sends no hook by itself), under the names `cd-k8` / `cd-k9` /
`cd-k10` / `cd-k11`. Spawning cases keep
the auth variables unset: each unsets `ANTHROPIC_API_KEY` and
`CLAUDE_CODE_OAUTH_TOKEN`, removes them from an already-running tmux
server's global environment, and checks neither reached the spawned
pane process's environment. kill-7 makes its session by hand like
kill-1, also sets the pane's `@ad_pane` (as agent-director's own create
does), and keeps the auth variables unset too; its `resume` runs with
the same `PATH` prefix, so a wrongly allowed launch would start only
the stand-in. kill-8 and kill-9 type a SessionStart (kill-8 also a
SessionEnd) into X's recorded pane with
`/opt/driver/pane-hook.sh <id> '<payload>'`, so the hook's parent is
the pane process (SR-22.9): kill-9's X moves `pending` → `waiting`,
and kill-8's X reports in and then ends while its agent and session
keep running. kill-10 and kill-11 synthesise no hook. kill-7 and kill-8
each write a `[tmux]` config at the safe minimums to
`~/.agent-director/config.toml` (kill-7 `starting_session_seconds =
60`; kill-8 that and `stopping_window_seconds = 30`), remove it in
their EXIT trap, and wait about a minute, so the session is past the
configured bound (and kill-8's row past the configured window) but
inside the defaults (300 s, 90 s). kill-9 writes no config file.

The pause cases exercise the `/exit` → poll-for-ended path against a
seeded row and a `cat` pane rather than a real Claude. `pause-3`
injects the post-`/exit` transition by writing directly to the SQLite
row, which mirrors what the real SessionEnd hook would do once Claude
actually exits; its background flip waits (bounded, 10s) until `/exit`
shows in the agent's pane, so the flip itself proves `/exit` reached
the labelled session's pane before the row ended (if `/exit` never
shows it flips anyway so `pause` returns, and the case fails). An EXIT
trap stops the flip and removes the session by `$N`. `pause-4` proves
the deadline math: with `pause.timeout_seconds=2` configured via a
per-test `~/.agent-director/config.toml` (removed by its EXIT trap),
the verb delivers `/exit`, waits ~2s and returns `ErrPauseTimeout`.

## Notes for the orchestrator

- Audit standard (SRD §17): run `make test-docker EPIC=epic-05-stop`
  yourself, inspect the JSON stream case-by-case, confirm each `t2`
  emitted `{"status":"pass"}`.
- `pause-4` uses a 2s timeout deliberately (not the 30s default) so
  the case runs in a few seconds.
- `kill-7` and `kill-8` each wait about a minute on purpose: the
  starting-session bound's and the stopping window's safe minimums
  (60 s, 30 s) are the shortest values the configuration accepts, and
  each case must run past them. Together they add about two minutes to
  the run.
- All cases avoid `tmux kill-server` — the operator denies that tool.
  Per-case cleanup is via `tmux kill-session -t <$N>` of the sessions
  the case made (an EXIT trap), plus the DB-reset's `cd-*` sweep.

## tmux session sweep

Cases that exercise real tmux leave sessions under the `cd-*` prefix.
The DB-reset fixture kills `cd-*` sessions between cases. The only
session made outside that prefix is kill-11's grouped `viewer`, which
kill-11 removes itself, by its session id on X's recorded socket, in an
EXIT trap (the kill normally takes it down with X's window).
