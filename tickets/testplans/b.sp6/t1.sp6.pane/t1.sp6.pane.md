# pane-stuck

Shell testplan for the `no_screen_change` stuck reason and
`no_screen_change_availability` (PRD t1.ob8.s4, SRD t1.ob8.gw, Epic
t1.sp6.rk). The driver resets a binary-derived store before each independent
case. No credentials or real agent are needed: a case spawns the stand-in
Claude or Codex (an interactive bash in a real tmux pane) and types its
`SessionStart` and `UserPromptSubmit` into the pane with
`/opt/driver/pane-hook.sh`, so the shipped binary samples a real owned pane on
every `status`, `get` and `list`. No case waits out a timeout: the committed
pane baseline has no public writer but a read, so a case moves its start
(`spawns.pane_since_ms`) back with `/opt/driver/sql.sh`, a reviewed exception
to the raw-SQL rule like permission-stuck's ownership columns. The Cursor case
seeds its rows and request with `sql.sh` too.

The cases cover, through public reads and refusals only, the pane episode
shown alike to independent processes, the per-spawn override recorded and
winning over the configuration, and Cursor's unavailability with its
permission detection retained. Expected wire values come from the shared
`cmd/agent-director/testdata/stuck/pane.json` and `permission.json`. Exact
timeout and settle boundaries, capture failures, races and reason switches
stay unit tests (`pkg/api/stuck_pane_test.go`, `stuck_pane_settle_test.go`).
Each case prints one compact JSON evidence line of observed values; on a
binary without the schema it prints `availability: unavailable` and exits 77,
never a pass. The runnable driver is `test/driver/pane-stuck.sh`.
