# install-12: way back to the previous release

b.ssz moved AD's directory from `~/.agent-director` to
`~/.config/agent-director` (SR-11.7). docs/operator-actions.md "Going back to
the previous release" (SR-11.6) is the one way to undo the upgrade, and
skills/install-agent-director/SKILL.md restates it. This case follows those
old-layout numbered steps, in order, from three starting points, each in its own HOME and each
against the snapshot of its own pre-upgrade install. It is also the literal
follow of the way-back branch of install.sh's failed-migration-write advice.

## Setup

Per-case DB-reset. Each row makes its own absolute mktemp `HOME` and builds the
old-layout install in it with `/opt/driver/old-layout.sh` (the previous release,
baked under `/opt/previous-release`, installed by its own `install.sh`: hooks,
MCP registration, PATH link, one `ended` Claude row, templates `worker` and
`reviewer`, `disable_askuserquestion = true`). The case adds a sentinel user
hook and a `model` key to `settings.json`, so that step 5's "remove only the
new-path entries" has something to leave alone. Every store read or write goes
through `/opt/driver/sql.sh`. No schema version is written down: the previous
release's expected `user_version` and table structure come from a reference
store that release made itself.

Before anything runs, the case reads the way-back section from
`/work/source/docs/operator-actions.md` and from
`/work/source/skills/install-agent-director/SKILL.md` and compares each, word
for word (Markdown links reduced to their text, whitespace runs collapsed),
with its own expected copy of the entire section, including the current-layout
backup/restore qualification and nine historical old-layout steps. Current-layout
rollback is covered by TestAdviceFollow_CurrentLayoutRollback in the sandbox
unit suite; the three rows here follow the historical old-layout procedure.
A change to a step in either
file turns the case red.

## Starting points (one row each)

| Row | Upgrade | What the way back must handle |
|---|---|---|
| `plain` | this release's `install.sh`, same flags, same directory: exit 0 | store inside the directory (step 4 has nothing to act on); `~/.agent-director` absent (step 3's first command has nothing to act on) |
| `outside` | the same, with the store outside the directory through `[store] db_path`; afterwards `~/.agent-director` is recreated (a marker file) and an older decoy `~/.agent-director.pre-move-20200101-000000` exists | step 3 sets the recreated directory aside as `.recreated-<ts>` and renames the NEWEST `pre-move-*` back, not the decoy; step 4 puts the pre-upgrade copy of the outside store back and deletes a `-wal`/`-shm` the copy lacks |
| `failed-write` | the same, with a `cp` stand-in first on PATH that fails the backup copy of `templates/worker.toml` with "No space left on device" (as E3-T3's test of the failed write does): exit 1 after the binary swap, store not opened | step 5 has nothing to act on (the install stopped before the hooks merge); the old registration is still there and step 6 removes it |

## Steps (each row)

1. Build the old-layout install, add the sentinel hook, snapshot its directory
   (`/opt/driver/tree-snapshot.sh`: path, kind, mode, sha256; a store is
   compared by `user_version`, table structure and a dump of its rows; an
   outside store also by a byte copy made before anything opened it).
2. Run the upgrade of the row.
3. Follow steps 1 to 9 of the documented way back, in order, with the
   documented commands. A step with nothing to act on in a row is logged as
   such. The previous release's reinstall uses the image's copy of its
   `install.sh` from its tag (`/opt/previous-release/install.sh`) in place of
   the fetch, with the flags of the original install. Step 7 is followed
   literally: the reinstall must print `registration failed (continuing
   anyway)`, then the documented `claude mcp add ... -s <scope> ...` and
   `claude mcp get` run with the scope step 6 showed. Step 1's schedule removal
   (`crontab -e`, `systemctl --user disable`, `rm` of the four units,
   `daemon-reload`) is not run: no row's upgrade passes `--schedule`, and the
   image has no systemd user manager and no cron daemon. The case checks that no
   unit file and no tagged crontab line exists and logs the step as having
   nothing to act on.
4. Check the result against the snapshot.

## Pass criteria (each row)

- The upgrade ends as the row says (exit 0; exit 1 with the failed-write
  headline, no `err_name` line, and the way back named in its advice).
- Every documented step is followed in order; each is logged either as acted
  on or as having nothing to act on.
- After step 7, `~/.agent-director` equals the pre-upgrade snapshot: the same
  paths, modes and bytes (`bin/`, `admin/` and the trail included), except the
  files the previous release's reinstall writes: a `config.toml.bak.<ts>` of
  its hooks merge. The store is at the previous release's `user_version` and
  structure with the same rows. An outside store's `state.db` is byte for byte
  its pre-upgrade copy (step 4 deletes the `-wal` and `-shm` the copy lacks; the
  reinstall's read leaves only an empty `-wal` and a `-shm`, SQLite's index).
- `~/.config/agent-director` is gone (set aside as `.after-upgrade-<ts>`),
  and the newest kept directory is the one renamed back; a recreated
  `~/.agent-director` is kept as `.recreated-<ts>`; an older kept directory
  is left alone.
- `settings.json` holds the previous release's help hooks naming the old path
  and no entry naming the new one, and equals the pre-upgrade file in every
  other entry (the sentinel hook and `model` included).
- `claude mcp get agent-director` names the old binary in the original scope.
  The PATH link points to the old binary.
- Step 9: the previous release's `list` reads the old row; `~/.config/agent-director`
  is not recreated; the store is unchanged by it.

## Script

```bash
set -euo pipefail
export LC_ALL=C

PREV=/opt/previous-release
INSTALL=/opt/skills/install-agent-director/install.sh
NEWBIN=/usr/local/bin/agent-director
NEWADMIN=/opt/bin/agent-director-admin
SQL=/opt/driver/sql.sh
SNAP=/opt/driver/tree-snapshot.sh
DOC=/work/source/docs/operator-actions.md
SKILL=/work/source/skills/install-agent-director/SKILL.md

T=$(mktemp -d /tmp/install-12-XXXXXX)
mkdir "$T/scratch"

# The driver keeps only the head and tail of a case's output, so every failure
# is also appended to $T/fails and repeated by the last line.
fail() {
    echo "FAIL: $*" >&2
    echo "$*" >>"$T/fails"
    exit 1
}

# ---- the documented steps, read from the docs ------------------------------------
# The section of a file, from its heading to the next "## " heading, Markdown
# links reduced to their text and whitespace runs collapsed (a re-wrapped line is
# not a changed step).
norm() { sed -E 's/\[([^]]*)\]\([^)]*\)/\1/g' | tr -s '[:space:]' ' ' | sed -E 's/^ //; s/ $//'; }
section() {
    awk '/^## Going back to the previous release$/ { f = 1; print; next } f && /^## / { exit } f' "$1" | norm
}
# The expected copy: the section as the two files must hold it.
cat >"$T/want.md" <<'EOF'
## Going back to the previous release

For an upgrade within the current `~/.config/agent-director` layout,
including schema v9→v10, v10→v11, v11→v12, v12→v13, v13→v14 and v14→v15,
the old-layout steps below do not apply. Before upgrading, stop agents, servers and callers
and keep a copy of the actual store (`[store] db_path` when set), including its `-wal` and
`-shm` files.
To roll back, stop them again, restore that pre-upgrade copy and install the
previous release with its own `install.sh` and the original install flags.
Restore the store with its companion files, removing a `-wal` or `-shm`
that the copy lacks, as in step 4 below. This loses all writes made since
the backup. The installer does not make this backup; a binary swap cannot
make a v15 store readable by a v9, v10, v11, v12, v13 or v14 binary. There is
no supported in-place downgrade from v15. The tested v12→v11 family-history
recipe applies only to a genuine family-only v12 store and cannot operate
on v13, v14 or v15; see the migration guide's emergency downgrade recipe. No supported
in-place reverse path crosses v11→v10 or v10→v9. A copy made after migration
cannot replace the pre-upgrade backup. Without a pre-upgrade copy, stop
and obtain human help.

The numbered procedure below applies only to an upgrade that moved
`~/.agent-director` to `~/.config/agent-director` and retained a
`~/.agent-director.pre-move-*` directory. Whatever was written since that
upgrade is lost: the previous release reads the directory as it was before
the move.

1. Stop whatever starts agents, then every agent, every `serve` and every
   caller. Remove the schedule `install.sh --schedule` added, if any, because
   its entries run the binary in the directory step 2 sets aside: delete the
   crontab lines tagged `agent-director-schedule` (`crontab -e`), or disable
   the timers and delete the four units:

   ```sh
   systemctl --user disable --now agent-director-find-missing.timer agent-director-expire.timer
   rm -- ~/.config/systemd/user/agent-director-find-missing.service ~/.config/systemd/user/agent-director-find-missing.timer ~/.config/systemd/user/agent-director-expire.service ~/.config/systemd/user/agent-director-expire.timer
   systemctl --user daemon-reload
   ```

   (Use `$XDG_CONFIG_HOME/systemd/user/` when that is set to an absolute path.
   `uninstall.sh` would also remove the binaries and hooks: do not run it for
   this.)
2. Set the new directory aside:

   ```sh
   mv -- ~/.config/agent-director ~/.config/agent-director.after-upgrade-$(date +%Y%m%d-%H%M%S)
   ```

3. If `~/.agent-director` exists again (something recreated it since the
   upgrade), set it aside too. Then rename the newest kept directory back. It
   holds the store, `config.toml` and templates as they were before the upgrade.

   ```sh
   mv -- ~/.agent-director ~/.agent-director.recreated-$(date +%Y%m%d-%H%M%S)
   ls -d ~/.agent-director.pre-move-*
   mv -- ~/.agent-director.pre-move-<newest> ~/.agent-director
   ```

   Run the first command only when the old path exists. The newest name is the
   one with the latest timestamp.
4. A store kept outside AD's directory (`[store] db_path`) was migrated in
   place by the upgrade. Put back the copy made before the upgrade: `state.db`
   with its `-wal` and `-shm`, deleting a `-wal` or `-shm` the copy lacks. Skip
   this when the store was inside the directory.
5. In `~/.claude/settings.json`, remove only the entries that hold a hook
   command starting with `~/.config/agent-director/bin/agent-director` (written
   out with your home directory). Leave every other entry. Check the result is
   valid JSON.
6. From the directory the upgrade ran in (for a `local` registration made
   inside a git repository, any directory of that repository), remove AD's MCP
   registration, if there is one, in the scope `claude mcp get agent-director`
   shows. A name registered in several scopes needs this once per scope:

   ```sh
   claude mcp get agent-director
   claude mcp remove agent-director -s <scope>
   ```

7. From the same directory, install the previous release with that release's
   own `install.sh`, fetched from its tag, with the flags the original install
   used (`--register-mcp`, `--no-hooks`, `--symlink-dir` and the rest). It puts
   back its help hooks. Its `--register-mcp` registers nothing with the current
   Claude Code (it prints `registration failed (continuing anyway)`), so when
   step 6 showed a registration, add it back by hand, in the scope step 6
   showed (`local`, `user` or `project`), with the old path:

   ```sh
   claude mcp add agent-director -s <scope> -- ~/.agent-director/bin/agent-director serve --stdio
   claude mcp get agent-director
   ```

   This release's `install.sh` cannot install the previous release: it refuses
   an earlier release's binaries.
8. Change back by hand what was changed by hand to the new path after the
   upgrade: help hooks in the `settings.json` of other `CLAUDE_CONFIG_DIR`
   folders, Codex MCP and help entries, scripts, `$PATH` entries and an MCP
   registration made by hand.
9. Start the caller's previous version.

Delete the `after-upgrade` and `recreated` directories once the previous
release is confirmed working; `uninstall.sh --purge` removes them.
EOF
norm <"$T/want.md" >"$T/want.norm"
[ "$(wc -w <"$T/want.norm")" -gt 300 ] || fail "the expected copy of the steps is too short"
for pair in "operator-actions.md:$DOC" "SKILL.md:$SKILL"; do
    label="${pair%%:*}" file="${pair#*:}"
    [ -f "$file" ] || fail "no $file"
    section "$file" >"$T/got.norm"
    if ! cmp -s "$T/want.norm" "$T/got.norm"; then
        tr ' ' '\n' <"$T/want.norm" >"$T/want.words"
        tr ' ' '\n' <"$T/got.norm" >"$T/got.words"
        diff "$T/want.words" "$T/got.words" | head -n 12 | tr '\n' ' ' >"$T/words.diff" || true
        fail "$label: the way-back section differs from the expected steps (word diff: $(cat "$T/words.diff"))"
    fi
    echo "docs: $label holds the nine steps word for word"
done
[ "$(grep -cE '^[0-9]\. ' "$T/want.md")" = 9 ] || fail "the expected copy does not hold nine numbered steps"
[ "$(cat $PREV/TAG)" = v0.11.1 ] || echo "note: the baked previous release is $(cat $PREV/TAG)"

# ---- reference stores, one per binary, made in a scratch HOME ---------------------
HOME="$T/scratch" "$PREV/agent-director" list --store-path "$T/ref-old.db" >/dev/null
HOME="$T/scratch" "$NEWBIN" list --store-path "$T/ref-new.db" >/dev/null
# A store's structure: each table's columns and each index's columns. Not
# `.sha3sum --schema` (it hashes the rows, and store_meta holds a random store_id).
schema_dump() {
    $SQL -readonly "$1" "SELECT 'T', m.name, p.cid, p.name, p.type, p.\"notnull\", p.dflt_value, p.pk FROM sqlite_master m, pragma_table_info(m.name) p WHERE m.type = 'table' ORDER BY m.name, p.cid;"
    $SQL -readonly "$1" "SELECT 'I', m.name, m.tbl_name, i.seqno, i.name FROM sqlite_master m, pragma_index_info(m.name) i WHERE m.type = 'index' ORDER BY m.name, i.seqno;"
}
schema_hash() { schema_dump "$1" | sha256sum | cut -d' ' -f1; }
# user_version, structure and a dump of every row, of one and the same file
# before and after: nothing migrated it in between.
store_full() { echo "$($SQL -readonly "$1" 'PRAGMA user_version') $(schema_hash "$1") $($SQL -readonly "$1" .dump | sha256sum | cut -d' ' -f1)"; }
store_ver() { $SQL -readonly "$1" 'PRAGMA user_version'; }
old_ver=$(store_ver "$T/ref-old.db")
new_ver=$(store_ver "$T/ref-new.db")
old_sch=$(schema_hash "$T/ref-old.db")
new_sch=$(schema_hash "$T/ref-new.db")
[ "$old_ver" -gt 0 ] || fail "previous release's user_version=[$old_ver]"
[ "$new_ver" -gt "$old_ver" ] || fail "this release's user_version [$new_ver] is not above the previous [$old_ver]"
[ "$old_sch" != "$new_sch" ] || fail "the two releases' schemas hash alike"

# A cp stand-in that fails the backup copy of one template, as E3-T3's test of
# the failed write does (a full disk). Every other cp runs the real one.
CPF="$T/cp-fails"
mkdir "$CPF"
cat >"$CPF/cp" <<EOF
#!/bin/bash
if [[ "\${!#}" == */templates/worker.toml.pre-agent-rename.* ]]; then
    echo 'cp: error writing: No space left on device' >&2
    exit 1
fi
exec "$(type -P cp)" "\$@"
EOF
chmod 0755 "$CPF/cp"

# ---- one starting point -----------------------------------------------------------
row() { # <kind>: plain | outside | failed-write
    local kind=$1
    local R="$T/$kind"
    local home="$R/home"
    mkdir -p "$home"
    : >"$R/say.log"
    export HOME="$home"
    export PATH="$home/.local/bin:/usr/local/bin:/usr/bin:/bin"
    cd "$home"
    say() {
        echo "[$kind] $*"
        echo "$*" >>"$R/say.log"
    }
    rfail() { fail "[$kind] $* (after: $(tail -n 1 "$R/say.log" | cut -c1-90))"; }
    local old="$home/.agent-director"
    local new="$home/.config/agent-director"

    # ---- setup: the old-layout install, a sentinel in settings.json, the snapshot
    local hargs=("$home") outdir=""
    if [ "$kind" = outside ]; then
        outdir="$R/outside"
        hargs+=(--store-outside "$outdir")
    fi
    /opt/driver/old-layout.sh "${hargs[@]}" >"$R/helper.out" 2>"$R/helper.err" || { tail -c 300 "$R/helper.err" >&2; rfail "old-layout.sh"; }
    kv() { sed -n "s/^$1=//p" "$R/helper.out"; }
    [ "$(kv dir)" = "$old" ] || rfail "helper dir=[$(kv dir)]"
    local oldbin olddb mcp_by
    oldbin=$(kv bin)
    olddb=$(kv db)
    mcp_by=$(kv mcp)
    [ "$mcp_by" != none ] || rfail "no MCP registration could be made (mcp=none)"
    [ "$kind" != outside ] || [ "$olddb" = "$outdir/state.db" ] || rfail "outside store is at [$olddb]"

    local settings="$home/.claude/settings.json"
    jq '. + {model: "sentinel-model"}
        | .hooks.SessionStart += [{hooks: [{type: "command", command: "echo user-session-hook"}]}]
        | .hooks.PreToolUse += [{matcher: "Bash", hooks: [{type: "command", command: "echo user-pre-tool-hook"}]}]' \
        "$settings" >"$R/settings.seed"
    cat "$R/settings.seed" >"$settings"
    cp -p "$settings" "$R/settings.before"
    [ "$(grep -cF "$oldbin help" "$settings")" -ge 1 ] || rfail "the old install wrote no help hook for $oldbin"

    local mcp_before scope_before scope_flag
    mcp_before=$(claude mcp get agent-director 2>&1 || true)
    grep -qF "$oldbin" <<<"$mcp_before" || rfail "old MCP registration does not name $oldbin"
    scope_before=$(sed -n 's/^ *Scope: *//p' <<<"$mcp_before")
    [ -n "$scope_before" ] || rfail "no Scope line in claude mcp get"
    scope_flag=$(sed -E 's/^([A-Za-z]+) config.*/\1/' <<<"$scope_before" | tr 'A-Z' 'a-z')
    case "$scope_flag" in local | project | user) ;; *) rfail "cannot read a scope from [$scope_before]" ;; esac

    # The pre-upgrade copy of an outside store, byte for byte, before anything
    # opens it. The store is idle: its -wal holds no bytes and its -shm is only
    # the shared-memory index of a closed store (the helper's last read-only
    # query leaves both). The copy an operator makes of such a store is state.db
    # alone, so it lacks a -wal and -shm, and step 4 has a -wal and -shm to delete
    # that the copy lacks. A -wal that held bytes would be copied with it.
    if [ -n "$outdir" ]; then
        mkdir "$R/precopy"
        cp -p "$olddb" "$R/precopy/state.db"
        [ ! -s "$olddb-wal" ] || cp -p "$olddb-wal" "$R/precopy/state.db-wal"
        say "setup: copy of the outside store: state.db$([ ! -e "$R/precopy/state.db-wal" ] || echo ' and its -wal'); the idle store's -shm and empty -wal are left out"
    fi
    local want_store_full
    want_store_full=$(store_full "$olddb")
    [ "$want_store_full" = "$old_ver $old_sch $(echo "$want_store_full" | cut -d' ' -f3)" ] \
        || rfail "the old store is not at the previous release's version and structure: $want_store_full"
    [ "$($SQL -readonly "$olddb" 'SELECT COUNT(*) FROM spawns')" = 1 ] || rfail "the old store does not hold the one row"
    $SNAP "$old" >"$R/old.full"
    grep -q $'^config.toml\t' "$R/old.full" || rfail "the snapshot holds no config.toml"

    # ---- the upgrade of the row
    local live_db="$new/state.db"
    [ -z "$outdir" ] || live_db="$olddb"
    say "upgrade: this release's install.sh, same flags, same directory"
    local rc
    set +e
    if [ "$kind" = failed-write ]; then
        PATH="$CPF:$PATH" "$INSTALL" --binary "$NEWBIN" --admin-binary "$NEWADMIN" --register-mcp >"$R/upgrade.out" 2>"$R/upgrade.err"
    else
        "$INSTALL" --binary "$NEWBIN" --admin-binary "$NEWADMIN" --register-mcp >"$R/upgrade.out" 2>"$R/upgrade.err"
    fi
    rc=$?
    set -e
    [ -d "$new" ] || rfail "the upgrade left no $new (exit $rc)"
    [ ! -e "$old" ] || rfail "the upgrade left $old (exit $rc)"
    local kept_n
    kept_n=$(ls -d "$home"/.agent-director.pre-move-* | wc -l)
    [ "$kept_n" = 1 ] || rfail "$kept_n kept directories after the upgrade; want 1"
    if [ "$kind" = failed-write ]; then
        [ "$rc" = 1 ] || { tail -c 400 "$R/upgrade.err" >&2; rfail "the upgrade exited $rc; want 1 (the failed migration write)"; }
        grep -qxF "install.sh: the agent-rename migration could not write $new/templates/worker.toml; stopping before the store is opened." "$R/upgrade.err" \
            || { tail -c 600 "$R/upgrade.err" >&2; rfail "no failed-write headline for worker.toml"; }
        ! grep -q '^install\.sh: err_name=' "$R/upgrade.err" || rfail "exit 1 carries an err_name line"
        tr -s '[:space:]' ' ' <"$R/upgrade.err" | grep -qF 'see "Going back to the previous release"' || rfail "the install's advice does not name the way back"
        [ "$(store_ver "$new/state.db")" = "$old_ver" ] || rfail "the store was opened: v$(store_ver "$new/state.db")"
        [ -z "$(ls "$new"/templates/worker.toml.pre-agent-rename.* 2>/dev/null)" ] || rfail "worker.toml has a backup"
        grep -q '^claude_args = ' "$new/templates/worker.toml" || rfail "worker.toml is not as it was"
        ls "$new"/config.toml.pre-agent-rename.* >/dev/null 2>&1 || rfail "config.toml was not migrated before the failure"
        say "upgrade: exit 1 after the binary swap, as E3-T3 does; store left at v$old_ver"
    else
        [ "$rc" = 0 ] || { tail -c 400 "$R/upgrade.err" >&2; rfail "the upgrade exited $rc"; }
        [ "$(store_ver "$live_db")" = "$new_ver" ] || rfail "the upgrade left the store at v$(store_ver "$live_db"); want v$new_ver"
        say "upgrade: exit 0; store at v$new_ver"
    fi
    if [ "$kind" = outside ]; then
        [ "$(store_ver "$olddb")" = "$new_ver" ] || rfail "the outside store was not migrated in place: v$(store_ver "$olddb")"
        ! cmp -s "$olddb" "$R/precopy/state.db" || rfail "the outside store equals its pre-upgrade copy after the upgrade"
        [ ! -e "$new/state.db" ] || rfail "an outside-store install holds $new/state.db"
        # What the upgrade's own reads left beside the store; a -wal or -shm the
        # copy lacks must be there for step 4 to delete.
        for sfx in -wal -shm; do
            [ ! -e "$R/precopy/state.db$sfx" ] || continue
            if [ -e "$olddb$sfx" ]; then
                say "upgrade: the live store has a state.db$sfx the copy lacks"
            else
                echo stray >"$olddb$sfx"
                say "upgrade: left no state.db$sfx; planted a stray one for step 4"
            fi
        done
        # Something recreates the old directory; an older kept directory exists.
        mkdir -m 0700 "$old"
        echo marker >"$old/recreated-marker"
        mkdir "$home/.agent-director.pre-move-20200101-000000"
        echo decoy >"$home/.agent-director.pre-move-20200101-000000/decoy"
    fi

    # ---- the way back, step by step (docs/operator-actions.md)
    say "step 1: stop whatever starts agents, then every agent, every serve and every caller"
    local running="" e tgt
    for e in /proc/[0-9]*/exe; do
        tgt=$(readlink "$e" 2>/dev/null || true)
        case "$tgt" in "$home"/.config/agent-director/* | "$home"/.agent-director*/*) running="$running $e->$tgt" ;; esac
    done
    if [ -z "$running" ]; then
        say "step 1: nothing to act on: no agent-director process runs (no serve, no caller, no agent)"
    else
        rfail "step 1: processes of the install are running:$running"
    fi
    # The schedule half of step 1: no row's upgrade passes --schedule, so there is
    # nothing to remove. The documented commands (crontab -e, systemctl --user, rm of
    # the four units) are not run: the image has no systemd user manager and no cron
    # daemon, so they would fail here, and there is nothing for them to act on. The
    # check below is that no unit file was written in the documented directory. The
    # crontab is not looked at: the image has no crontab program and no spool this
    # user could read, so a grep of /var/spool/cron could never fail and would prove
    # nothing; the crontab side is covered by the Go cases (schedule_test.go).
    local sched_left="" u
    for u in find-missing.service find-missing.timer expire.service expire.timer; do
        [ ! -e "$home/.config/systemd/user/agent-director-$u" ] || sched_left="$sched_left agent-director-$u"
    done
    [ -z "$sched_left" ] || rfail "step 1: the upgrade (no --schedule) left a schedule:$sched_left"
    say "step 1: schedule: nothing to act on: the upgrade did not pass --schedule; the commands that remove one are not run (no systemd user manager or cron daemon in the image)"

    say "step 2: set the new directory aside"
    mv -- ~/.config/agent-director ~/.config/agent-director.after-upgrade-$(date +%Y%m%d-%H%M%S)
    [ ! -e "$new" ] || rfail "step 2: $new is still there"
    [ "$(ls -d "$home"/.config/agent-director.after-upgrade-* | wc -l)" = 1 ] || rfail "step 2: not one after-upgrade directory"

    say "step 3: set a recreated ~/.agent-director aside; rename the newest kept directory back"
    if [ -e ~/.agent-director ]; then
        mv -- ~/.agent-director ~/.agent-director.recreated-$(date +%Y%m%d-%H%M%S)
        say "step 3: ~/.agent-director existed: set aside"
    else
        say "step 3: first command: nothing to act on: ~/.agent-director does not exist"
    fi
    ls -d ~/.agent-director.pre-move-*
    local newest
    newest=$(ls -d ~/.agent-director.pre-move-* | sed 's/.*\.pre-move-//' | sort | tail -n 1)
    [ -n "$newest" ] || rfail "step 3: no pre-move directory"
    mv -- ~/.agent-director.pre-move-"$newest" ~/.agent-director
    say "step 3: renamed pre-move-$newest back"
    [ -d "$old" ] || rfail "step 3: no $old"

    say "step 4: a store outside AD's directory"
    if grep -q '^db_path *=' ~/.agent-director/config.toml; then
        [ -n "$outdir" ] || rfail "step 4: the restored config.toml names an outside store in a row that has none"
        local sfx had
        for sfx in "" -wal -shm; do
            had=absent
            [ ! -e "$olddb$sfx" ] || had=present
            if [ -e "$R/precopy/state.db$sfx" ]; then
                cp -p "$R/precopy/state.db$sfx" "$olddb$sfx"
                say "step 4: state.db$sfx: put back from the copy (the live one was $had)"
            else
                rm -f "$olddb$sfx"
                say "step 4: state.db$sfx: the copy lacks it; deleted the live one ($had)"
            fi
        done
        cmp "$R/precopy/state.db" "$olddb" || rfail "step 4: the outside state.db is not its pre-upgrade copy"
        for sfx in -wal -shm; do
            if [ -e "$R/precopy/state.db$sfx" ]; then
                cmp "$R/precopy/state.db$sfx" "$olddb$sfx" || rfail "step 4: state.db$sfx differs from the copy"
            else
                [ ! -e "$olddb$sfx" ] || rfail "step 4: state.db$sfx is left though the copy lacks it"
            fi
        done
    else
        [ -z "$outdir" ] || rfail "step 4: the restored config.toml has no db_path in the outside row"
        say "step 4: nothing to act on: the store was inside the directory"
    fi

    say "step 5: remove only the entries holding a hook command starting with the new path"
    local prefix="$home/.config/agent-director/bin/agent-director" n_new
    n_new=$(jq --arg p "$prefix" '[.. | .command? // empty | select(type == "string" and startswith($p))] | length' "$settings")
    jq --arg p "$prefix" '
        def holds: (.hooks // []) | any(.command? // "" | startswith($p));
        if .hooks then .hooks |= (with_entries(.value |= map(select(holds | not))) | with_entries(select(.value != []))) else . end
        | if .hooks == {} then del(.hooks) else . end' "$settings" >"$R/settings.step5"
    jq -e . "$R/settings.step5" >/dev/null || rfail "step 5: the result is not valid JSON"
    cat "$R/settings.step5" >"$settings"
    [ "$(jq --arg p "$prefix" '[.. | .command? // empty | select(type == "string" and startswith($p))] | length' "$settings")" = 0 ] \
        || rfail "step 5: an entry for the new path is left"
    jq -e . "$settings" >/dev/null || rfail "step 5: settings.json is not valid JSON"
    if [ "$n_new" = 0 ]; then
        say "step 5: nothing to act on: no hook command names $prefix (the install stopped before the hooks merge)"
        [ "$kind" = failed-write ] || rfail "step 5: no new-path entry in a row whose upgrade merged the hooks"
    else
        say "step 5: removed $n_new new-path hook command(s)"
        [ "$kind" != failed-write ] || rfail "step 5: new-path entries after a failed upgrade"
    fi
    grep -qF user-session-hook "$settings" && grep -qF user-pre-tool-hook "$settings" && [ "$(jq -r .model "$settings")" = sentinel-model ] \
        || rfail "step 5: an entry that is not AD's was removed"

    say "step 6: remove AD's MCP registration in the scope claude mcp get shows"
    local n_reg=0 got scope step6_scope=""
    while :; do
        got=$(claude mcp get agent-director 2>&1) || got=""
        scope=$(sed -n 's/^ *Scope: *\([A-Za-z]*\) config.*/\1/p' <<<"$got" | tr 'A-Z' 'a-z')
        [ -n "$scope" ] || break
        step6_scope=$scope
        n_reg=$((n_reg + 1))
        [ "$n_reg" -le 3 ] || rfail "step 6: the registration is still there after 3 removals"
        claude mcp remove agent-director -s "$scope" >"$R/mcp-remove.$n_reg" 2>&1 || { cat "$R/mcp-remove.$n_reg" >&2; rfail "step 6: claude mcp remove -s $scope failed"; }
        say "step 6: removed the registration in scope $scope (names: $(grep -m1 'Command:' <<<"$got" | sed 's/^ *//'))"
    done
    if [ "$n_reg" = 0 ]; then
        say "step 6: nothing to act on: no registration"
    fi
    [ "$n_reg" -ge 1 ] || rfail "step 6: the upgrade should have left a registration to remove"
    ! claude mcp get agent-director >/dev/null 2>&1 || rfail "step 6: claude mcp get still finds the registration"

    say "step 7: install the previous release with its own install.sh, the original flags"
    set +e
    "$PREV/install.sh" --binary "$PREV/agent-director" --admin-binary "$PREV/agent-director-admin" --register-mcp >"$R/prev-install.out" 2>"$R/prev-install.err"
    rc=$?
    set -e
    [ "$rc" = 0 ] || { tail -c 400 "$R/prev-install.err" >&2; rfail "step 7: the previous release's install.sh exited $rc"; }
    [ -n "$step6_scope" ] || rfail "step 7: step 6 showed no registration, so the scope to add back is unknown"
    [ "$step6_scope" = "$scope_flag" ] || rfail "step 7: step 6 showed scope [$step6_scope]; the old install was in [$scope_flag]"
    got=$(claude mcp get agent-director 2>&1 || true)
    if grep -qF 'registration failed (continuing anyway)' "$R/prev-install.out" "$R/prev-install.err"; then
        # What the doc says: this Claude Code refuses the previous release's `claude
        # mcp add <name> <path> serve --stdio` form (b.fom), so the reinstall prints
        # 'registration failed (continuing anyway)' and registers nothing.
        say "step 7: the previous release printed 'registration failed (continuing anyway)'"
        ! grep -qF "$oldbin" <<<"$got" || rfail "step 7: it printed 'registration failed' yet claude mcp get names $oldbin"
        # Then the documented commands, with the scope step 6 showed and the old
        # path (~ is $home here).
        say "step 7: step 6 showed scope $step6_scope: adding the registration back with the documented commands"
        claude mcp add agent-director -s "$step6_scope" -- ~/.agent-director/bin/agent-director serve --stdio >"$R/mcp-add.out" 2>&1 || { cat "$R/mcp-add.out" >&2; rfail "step 7: the documented claude mcp add failed"; }
        got=$(claude mcp get agent-director 2>&1) || rfail "step 7: the documented claude mcp get found no registration"
    else
        # The doc's "when step 6 showed a registration": a previous release that
        # registers itself leaves nothing to add by hand.
        say "step 7: the previous release did not print 'registration failed'; its own install.sh registered"
        grep -qF "$oldbin" <<<"$got" || rfail "step 7: no 'registration failed' from the previous release and no registration with $oldbin: $(tr '\n' ' ' <<<"$got" | head -c 200)"
    fi
    [ "$oldbin" = "$home/.agent-director/bin/agent-director" ] || rfail "step 7: the old binary is [$oldbin], not ~/.agent-director/bin/agent-director"
    grep -qF "$oldbin" <<<"$got" || rfail "step 7: claude mcp get does not name $oldbin"
    ! grep -qF "$new" <<<"$got" || rfail "step 7: claude mcp get names the new directory"
    [ "$(sed -n 's/^ *Scope: *//p' <<<"$got")" = "$scope_before" ] || rfail "step 7: the registration's scope is not [$scope_before]"

    say "step 8: nothing to act on: nothing was changed by hand to the new path in this setup"

    # ---- the result, against the snapshot, before anything starts
    say "check: ~/.agent-director equals the pre-upgrade snapshot"
    $SNAP "$old" >"$R/after.full"
    cut -f1 "$R/old.full" | sort >"$R/p-old"
    cut -f1 "$R/after.full" | sort >"$R/p-after"
    comm -23 "$R/p-old" "$R/p-after" >"$R/removed"
    comm -13 "$R/p-old" "$R/p-after" >"$R/added"
    awk -F'\t' 'NR==FNR{o[$1]=$0; next} ($1 in o) && o[$1]!=$0 {print $1}' "$R/old.full" "$R/after.full" >"$R/changed"
    [ ! -s "$R/removed" ] || rfail "files of the snapshot are gone: $(tr '\n' ' ' <"$R/removed")"
    # The previous release's reinstall rewrites config.toml (its hooks merge,
    # which also leaves the .bak below) and creates the file with the umask's mode:
    # the bytes are the same; a 0600 file comes back 0644. Named here, nothing else.
    if [ -s "$R/changed" ]; then
        [ "$(cat "$R/changed")" = config.toml ] || rfail "files differ from the snapshot: $(tr '\n' ' ' <"$R/changed")"
        [ "$(awk -F'\t' '$1 == "config.toml" {print $4}' "$R/old.full")" = "$(awk -F'\t' '$1 == "config.toml" {print $4}' "$R/after.full")" ] \
            || rfail "the reinstall changed config.toml's bytes"
        say "check: the reinstall left config.toml's bytes and changed its mode $(awk -F'\t' '$1 == "config.toml" {print $3}' "$R/old.full") -> $(awk -F'\t' '$1 == "config.toml" {print $3}' "$R/after.full")"
    fi
    # What the previous release's reinstall writes: the .bak of its config.toml merge.
    sed -E 's/\.bak\.[0-9][0-9-]*$/.bak.<ts>/' "$R/added" >"$R/added.norm"
    if [ -s "$R/added.norm" ]; then
        [ "$(grep -vxF 'config.toml.bak.<ts>' "$R/added.norm" | wc -l)" = 0 ] || rfail "files the reinstall added: $(tr '\n' ' ' <"$R/added.norm")"
        say "check: the reinstall added only $(tr '\n' ' ' <"$R/added.norm")"
    fi
    if [ -n "$outdir" ]; then
        cmp "$R/precopy/state.db" "$olddb" || rfail "the outside store is not byte for byte its pre-upgrade copy"
        # The previous release's reinstall reads the store (read-only), which
        # leaves a -shm (SQLite's shared-memory index, rebuilt on open) and may
        # leave an empty -wal: neither holds data, so state.db and a non-empty
        # -wal are what must equal the copy.
        if [ -e "$R/precopy/state.db-wal" ]; then
            cmp "$R/precopy/state.db-wal" "$olddb-wal" || rfail "the outside state.db-wal differs from the copy"
        else
            [ ! -s "$olddb-wal" ] || rfail "the outside state.db-wal holds bytes the copy lacks"
        fi
        say "check: the outside store is byte for byte its pre-upgrade copy"
    fi
    [ "$(store_full "$olddb")" = "$want_store_full" ] || rfail "the store's version, structure or rows differ from the pre-upgrade store"
    say "check: the store is at user_version $old_ver, structure and rows as before"
    [ "$(jq -S 'walk(if type == "array" then sort_by(tojson) else . end)' "$settings")" = "$(jq -S 'walk(if type == "array" then sort_by(tojson) else . end)' "$R/settings.before")" ] \
        || { diff <(jq -S . "$R/settings.before") <(jq -S . "$settings") >&2 || true; rfail "settings.json differs from the pre-upgrade file"; }
    [ "$(grep -cF "$oldbin help" "$settings")" -ge 1 ] || rfail "settings.json holds no help hook for $oldbin"
    ! grep -qF "$new" "$settings" || rfail "settings.json still names $new"
    [ "$(readlink "$home/.local/bin/agent-director")" = "$oldbin" ] || rfail "the PATH link does not point to $oldbin"
    cmp "$PREV/agent-director" "$oldbin" || rfail "the restored agent-director is not the previous release's"
    [ ! -e "$new" ] || rfail "$new exists"
    [ "$(ls -d "$home"/.config/agent-director.after-upgrade-* | wc -l)" = 1 ] || rfail "no after-upgrade directory"
    if [ "$kind" = outside ]; then
        [ "$(ls -d "$home"/.agent-director.recreated-* | wc -l)" = 1 ] || rfail "the recreated directory was not kept as .recreated-<ts>"
        [ -f "$home"/.agent-director.recreated-*/recreated-marker ] || rfail "the .recreated directory lost its marker"
        [ ! -e "$old/recreated-marker" ] || rfail "the recreated directory's marker is in $old"
        [ -f "$home/.agent-director.pre-move-20200101-000000/decoy" ] || rfail "the older kept directory was touched"
        [ ! -e "$old/decoy" ] || rfail "the older kept directory was renamed back"
        [ "$(ls -d "$home"/.agent-director.pre-move-* | wc -l)" = 1 ] || rfail "the newest kept directory is still there"
    else
        [ -z "$(ls -d "$home"/.agent-director.pre-move-* "$home"/.agent-director.recreated-* 2>/dev/null)" ] || rfail "a kept or recreated directory is left"
    fi

    say "step 9: start the caller's previous version"
    local listed
    listed=$(agent-director list) || rfail "step 9: the previous release's list failed"
    [ "$(command -v agent-director)" = "$home/.local/bin/agent-director" ] || rfail "step 9: agent-director on PATH is $(command -v agent-director)"
    jq -e . >/dev/null <<<"$listed" || rfail "step 9: list printed no JSON: $(head -c 200 <<<"$listed")"
    grep -qF old-layout-1 <<<"$listed" || rfail "step 9: list does not show the old row: $(head -c 300 <<<"$listed")"
    [ ! -e "$new" ] || rfail "step 9: the previous release recreated $new"
    [ "$(store_full "$olddb")" = "$want_store_full" ] || rfail "step 9: list changed the store"
    [ -z "$outdir" ] || cmp "$R/precopy/state.db" "$olddb" || rfail "step 9: list changed the outside state.db"
    say "ok"
}

# ---- the rows ---------------------------------------------------------------------
rows_failed=""
for kind in plain outside failed-write; do
    set +e
    ( set -e; row "$kind" )
    rc=$?
    set -e
    [ "$rc" = 0 ] || rows_failed="$rows_failed $kind"
done
[ -z "$rows_failed" ] || fail "starting points that failed:$rows_failed: $(cut -c1-200 "$T/fails" | tr '\n' '|')"

rm -rf "$T"
echo "install-12 ok: the way back followed step by step from three starting points (plain, outside store with a recreated directory, failed migration write)"
