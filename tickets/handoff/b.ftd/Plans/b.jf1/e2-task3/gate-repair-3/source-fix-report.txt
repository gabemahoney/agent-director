Existing single connection/BEGIN IMMEDIATE/SQL binding and request acknowledgement/native claim predicates remain. Expiry is checked after acquisition, independent evidence and the request query. 2. internal/cursorhost/requests.go: compute the already-existing min(transport frame deadline, applicable immutable request approval/settlement/native deadline) before constructing both guards, and pass that same bound to CheckCursorAnswer. The shared callback and guard recheck terminal/relay retirement/expiry after independent runtime/pane evidence and again after the store transaction. Both initial and final protocol guards remain untouched; no protocol write retry/replay or uncertain-output semantics changed.
3. internal/cursorhost/report.go: factor existing post-hook report verification into verifyReport, reused by an optional PRIVATE reportWaiting registration immediately before direct hook execution. A terminal Enter during SessionStart/Stop may independently confirm the actual committed waiting row while the hook subprocess finishes. The stricter consumption check requires waiting, newer row version, matching launch/life/session/path, exact registered runtime/connection/pipes, no held unproven awaiting request, and independent runtime/pane evidence. The original post-hook verification still runs and can fail the session. Registration alone grants no admission and does not block the terminal reader until the hook finishes.
4. NEW internal/cursorhost/admission.go: private promptAdmission serializes one idle reservation and report handoff under a mutex, retaining atomic CompareAndSwap for ordinary ready admission. During a waiting report, one Enter can reserve only after its independent commit/evidence check succeeds. A claimed reservation remains claimed when the report returns: confirm cannot accidentally arm a second prompt. Pending/busy input is rejected when its Enter is consumed and its accepted=false event remains false after a later report. Disable clears the callback; deferred disable prevents stale verification against torn-down resources.
5. internal/cursorhost/session.go: use that private admission state for the same terminal reader. SessionStart with an initial saved prompt registers no idle admission, preserving initial prompt priority. Stop registers the waiting confirmation. Both complete their handoff without rearming a reservation already consumed during the hook tail. Unsupported /new and /clear still print their existing refusal; removed their redundant ready=true write because these control strings never consume admission and must not rearm an already-reserved prompt. Busy/new/clear controls remain green. No busy input queue or E3 work.
