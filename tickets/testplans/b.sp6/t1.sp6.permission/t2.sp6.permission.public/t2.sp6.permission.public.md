# Every agent's fallen-back permission request reads check_permission through independent reads, however long it waits

Maps to b.zpv's rule: a row with an open, relay-tracked permission request is
never shown as `needs_intelligence`, however long that request waits; it stays
`check_permission`, and `list --state check_permission` lists it. Cursor with
the relay off counts as relay-tracked. A read still establishes and persists
the request's fallback clock, and `[state] needs_intelligence_timeout_seconds`
still loads, with no effect.

## Setup

The DB-reset fixture gives a fresh store at the binary's current schema. The
driver checks the store has the v14 columns it seeds and reads
(`spawns.observation_version`, `display_observation`, `display_exit`,
`idle_screen_timeout_seconds`, `permission_epoch` and the request ownership
and clock columns); a binary without them prints `availability: unavailable`
and exits 77. It writes `[state] settle_ms = 0` and
`needs_intelligence_timeout_seconds = 1` to `config.toml`. All SQL uses
`/opt/driver/sql.sh`; no prior case or wall-clock delay supplies evidence.

## Steps

1. Insert 4 `check_permission` spawns: `public-claude`, `public-codex` and
   `public-cursor` with the relay on, and `public-cursor-off`, a Cursor spawn
   with the relay off (each session `ts-<id>`, launch token
   `1111111111111111`, `permission_epoch` 7). Give each one request (token
   `aaaaaaaa-aaaa-4aaa-aaaa-aaaaaaaaaaaa`, tool `Bash`) owned by that launch
   and epoch, its `confirm_by` (`settled_at`) 2020-01-01, admitted a second
   earlier, with no `fallback_at` or `fallback_basis`.
2. Confirm the request's `fallback_at` and `fallback_basis` are empty.
3. Run `agent-director status --instance-id <id>` until
   `spawns.observation_version` moves, at most 5 reads at the same state. It
   must move by exactly 1. Read the request's `fallback_at` and
   `fallback_basis`.
4. Run `status`, then `get` (a fresh process), for the same id. Read
   `observation_version` again, the raw `spawns.state`, then the trail
   records whose `instance_id` is the id.
5. Run `agent-director list --state check_permission --limit 4`, then
   `agent-director list --state needs_intelligence`.

## Pass criteria

- Step 3 stores the fallback clock: `fallback_at` 2020-01-01 (in
  milliseconds) with basis `deadline` for the 3 relay-on rows, and the
  admission a second earlier with basis `admission` for `public-cursor-off`.
- Every `status` and `get` row has state `check_permission`,
  `idle_screen_availability` `available` for Claude and Codex and
  `unavailable` for Cursor, and no `displayed_state`, `since`,
  `request_token`, `tool_name`, `unchanged_minutes` or `stuck_reason`
  member. Each `status` row's keys are exactly `context`, `family_state`,
  `idle_screen_availability` and `state`. Each `get` row's
  `permission_requests` holds the one request, with `delivery`
  `fallen_back`.
- `observation_version` is unchanged by step 4's reads; the raw
  `spawns.state` is still `check_permission`.
- `list --state check_permission --limit 4` returns exactly the 4 ids, each
  with state `check_permission` and its agent's `idle_screen_availability`.
  Leaving out `ended_at`, `launch_started_at`, `liveness_note`,
  `liveness_unverified_since` and `parent_id`, each row's keys are exactly
  `agent`, `cwd`, `family_state`, `idle_screen_availability`, `instance_id`,
  `labels`, `last_seen_at`, `permission_requests`, `relay_mode`,
  `started_at`, `state`, `state_changed_at` and `tmux_session_name`.
  `list --state needs_intelligence` exits 0 with no rows.
- For each id the trail holds no `ad.spawn.displayed_state_transition`
  record, no `ad.spawn.stuck_transition` record, and no
  `ad.spawn.state_transition` record naming `needs_intelligence` or
  `idle_screen`.
- The evidence line shows the timeout, the state shown, each row's clock
  basis, each row's `observation_version`, the list size, the
  `needs_intelligence` list size and the record count.
