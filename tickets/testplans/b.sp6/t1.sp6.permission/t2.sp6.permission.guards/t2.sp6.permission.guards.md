# Displayed needs_intelligence preserves live command authority

Maps to the report-only guarantee: a displayed `needs_intelligence` never
changes what `send-keys`, `decide` and `pause` may do, and a refusal writes
no trail record (PRD t1.ob8.s4, SRD t1.ob8.gw SR-5.2, acceptance criterion
11 of Epic t1.sp6.6s).

## Setup

As for the public case, but per agent a spawn `guard-<agent>` with one
fixture-token request. Each is first shown `needs_intelligence`: `status`
until `observation_version` moves by exactly 1 (at most 5 reads), then a
confirming read.

## Steps

1. For each of `claude`, `codex` and `cursor`, run
   `agent-director send-keys --instance-id guard-<agent> --text next`.
2. Run `agent-director decide --instance-id guard-<agent> --request-token <fixture token> --decision allow --max-wait-ms 0`.
   A zero wait cannot wait for a store lock, so under load it may refuse
   `ErrStoreBusy`, recording nothing: rerun it, every 100 ms for at most
   10 s, only while that is its refusal. Any other outcome ends the retry.
3. Run `agent-director pause --instance-id guard-<agent>`.
4. Read the request's `decision`, `proven_gone_at` and `pane_answer` with
   `sql.sh`, then run `status` again and read the trail records whose
   `instance_id` is `guard-<agent>`.

## Pass criteria

- The confirming read and the second `status` each have state
  `needs_intelligence`, the fixture's token and tool, `tmux_session_name`
  `ts-guard-<agent>`, `idle_screen_availability` `available` for Claude and
  Codex and `unavailable` for Cursor, and exactly the status keys the public
  case lists; the second `status` has the same `since` as the first.
- Steps 1 and 2 each exit non-zero with a stderr JSON envelope whose
  `err_name` is `ErrRelayFallenBack`; step 3 exits non-zero with `err_name`
  `ErrSpawnNotPausable`, for all 3 agents. A step 2 success, any other
  refusal, or `ErrStoreBusy` still answered after the 10 s retry fails the
  case.
- The request row is `decision` empty, `proven_gone_at` empty, `pane_answer`
  `none` (read as `||none`), and the raw `spawns.state` is still
  `check_permission`.
- Per id the trail holds exactly one `ad.spawn.displayed_state_transition`
  record, the entry, with exactly the keys `instance_id`, `prior_state`,
  `new_state`, `event` and `ts`, `prior_state` `check_permission`,
  `new_state` `needs_intelligence` and `ts` equal to the `since`; the
  refusals add none. No `ad.spawn.stuck_transition` record exists for the
  id, and no `ad.spawn.state_transition` record names `needs_intelligence`
  or `idle_screen`.
- The evidence line shows each verb's observed `err_name`, the request
  facts, the state shown and the record count per id.
