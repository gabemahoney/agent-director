

## E3 Task 2 technical decisions — coordinator, 2026-10-15

These implementation decisions are recorded from the completed source pass and remain subject to behavioral and independent source review before local commit; no Task 2 integration or authenticated acceptance is claimed.

- clear/new share the independent control mailbox lane. The first control advances cancellation authority immediately; repeated aliases coalesce with an explicit count/ignored disposition without a second request or deadline extension.
- Outstanding prompt requires its correlated validated terminal response, or positive zero-byte retirement at the existing start/writer gate. Idle rotates immediately without waiting for a nonexistent cancel-notification response. Existing three-second first-control deadline supervises cancellation, new-session creation, publication and protected-record waits; the new-session writer checks epoch and original expiry before bytes.
- Complete rotation input is provisionally reserved separately, bounded at 32 entries/8 MiB and the existing 1 MiB individual limit. It is not conversation admission. After publication it remains provisional until CheckCursorPrompt independently accepts all durable guards. Promotion transfers reservation ownership to the accepted FIFO; original monotonic observation order merges it ahead of newer ordinary admissions.
- Fresh session IDs must be nonempty, bounded, without whitespace normalization or NUL/CR/LF, and distinct from all previously confirmed IDs on the connection. Session-creation results must correlate to the single pending request. Confirmed IDs are bounded by the existing connection request cap.
- New Store.RotateCursorSession uses existing bounded immediate transaction, cursorAuthority, hookGateSQL, full examined snapshot and launch identity, existing state/settle writer, required upsertSessionHistoryEntry, conditional runtime update and mutation trails. Row identity/path, runtime and outgoing history commit together. No migration or generic history-policy change; SetCursorRuntimeSession remains startup-only.
- A narrow SessionStart payload adds cursor_previous_session and absolute cursor_rotation_deadline. Handler still requires real immediate gateway parent and existing independent verifier. New VerifyCursorRotation rechecks runtime/protected path/pane from the transaction-read row, avoiding recursive acquisition of the single store connection. CLI wiring supplies the real implementation.
- Required archive failure rolls back all publication writes. Reporter additionally verifies outgoing current-life history/path and complete new binding. A bounded supervisor receives the operation-observed identity through a buffered completion channel, including commits preceding later report errors. It never blocks on an unsupervised reconciliation read or claims rollback after possible publication.
- Existing durable permission/plan holds survive cancellation and rotation. Unknown origin never receives main-turn proof. New held work remains blocked by CheckCursorPrompt and both original guarded writers. New authorization records retain their admitted session identity; old exact tool/request IDs cannot acquire current authority.
- Known retired response IDs use a bounded numeric retirement watermark; known old session events and old authorization identities are inspectable without current lifecycle, prompt completion, answer or held-release authority. Missing current update attribution is fail-closed. Owned-runtime death checks precede retired event handling.
- Exit/eligible public pause preempt every supervised phase and retain genuine owned-process termination before SessionEnd. Interrupt during rotation fails closed and terminates the owned runtime; it refuses held input and never silently resumes the outgoing conversation.
- Reuse the single protected launch transcript. Held/refused records have no admitted session ID. Accepted input captures its session at consumption alongside the R1 cancellation epoch so a delayed old admission retains outgoing attribution after publication. Rotation-requested, confirmed, published, failed, held, refusal and existing individual old cancellation/start/outcome records remain distinct. No replay storage.
- Persistence exhaustion never extends the original cancellation deadline to manufacture final records. Every observed held ID gets visible refusal at cleanup; protected final dispositions are written only while recorder and original remaining budget permit. Already durable publication is not undone by later transcript failure.

Model assessment: No spec/tla inputs changed; TLA+ not applicable, zero formal or baseline jobs. Existing Phase5Hook Rotate/hold models do not model the new controller rotation phases, fresh-ID correlation, atomic three-write publication, held reservation/promotion/order or transcript publication boundaries. They are not proof of this implementation. Behavioral owner must assess the actual transitions; only demonstrated spec/model changes justify affected-only scheduler jobs.
