# resume-8: ended_at is cleared on resurrection

Per SRD §8.1 + the store contract: `resume` moves the finished row to
`pending` (a launch in progress) and that move clears `ended_at`; when
SessionStart on the resurrected Claude fires, the row goes `pending` →
`waiting` and `ended_at` stays NULL. This is the store-side half of the
resume contract. Epic 8 (`t1.h98.xw`, SR-20.9, SR-22.9): a hook moves
the row only when it comes from the row's own pane process, so every
hook is typed into the row's pane, and the last SessionStart into the
pane the resume created.

## Setup

Per-case DB-reset. The spawn and the resume run with
`PATH=/opt/driver/stand-in-claude:$PATH` prefixed to the
`agent-director` command, so the pane process is the stand-in claude's
interactive bash, which never reports in by itself. Hooks are typed into
the row's recorded pane with `/opt/driver/pane-hook.sh <id> '<payload>'`
(see the collector's "Driver mode").

## Steps

1. Spawn → SessionStart typed into the pane → seed JSONL → SessionEnd
   typed into the pane. Row state is `ended` with ended_at populated.
2. Verify ended_at is non-null (precondition).
3. Free tmux session.
4. `resume` → the row is `pending` and its `ended_at` is cleared.
5. Type a fresh SessionStart into the resumed pane (the stand-in does
   not drive this itself; `pane-hook.sh` reads the pane the resume
   recorded) → the row goes `pending` → `waiting`.
6. Row state is `waiting` AND ended_at is NULL.

## Pass criteria

- After SessionEnd, ended_at is non-null (precondition).
- Right after resume, the row is `pending`.
- After resume + simulated SessionStart, ended_at is NULL.
- Row state is `waiting`.

## Script

```bash
set -euo pipefail
standin_path="/opt/driver/stand-in-claude:$PATH"
id=$(PATH="$standin_path" agent-director spawn --cwd /tmp | jq -r '.claude_instance_id')
sess=$(agent-director get --claude-instance-id "$id" | jq -r '.tmux_session_name')

session_id="r8-session-uuid"
# transcript_path is the real on-disk path; the hook persists it as the
# row's jsonl_path, which resume Stats pre-flight (b.93m). Typed into the
# row's pane: SR-22.9 applies a hook only from the recorded pane process.
jsonl_path="$HOME/.claude/projects/-tmp/${session_id}.jsonl"
/opt/driver/pane-hook.sh "$id" \
    "{\"hook_event_name\":\"SessionStart\",\"transcript_path\":\"${jsonl_path}\"}" >/dev/null

mkdir -p "$HOME/.claude/projects/-tmp"
echo '{}' > "$jsonl_path"

/opt/driver/pane-hook.sh "$id" '{"hook_event_name":"SessionEnd","reason":"logout"}' >/dev/null

ended_before=$(sqlite3 "$HOME/.agent-director/state.db" \
    "SELECT ended_at FROM spawns WHERE claude_instance_id='$id';")
if [ -z "$ended_before" ]; then
    echo "FAIL: precondition ended_at empty after SessionEnd"; exit 1
fi

tmux kill-session -t "$sess" 2>/dev/null || true
PATH="$standin_path" agent-director resume --claude-instance-id "$id" >/dev/null

# The move to pending happened (the stand-in never reports in by itself).
state=$(agent-director get --claude-instance-id "$id" | jq -r '.state')
if [ "$state" != "pending" ]; then
    echo "FAIL: after resume state=$state; want pending"; exit 1
fi

# Synth a fresh SessionStart for the resumed claude, typed into the pane
# the resume created. New session uuid so the rotation behavior is also
# exercised.
new_session_id="r8-session-uuid-resumed"
new_jsonl_path="$HOME/.claude/projects/-tmp/${new_session_id}.jsonl"
mkdir -p "$HOME/.claude/projects/-tmp"
echo '{}' > "$new_jsonl_path"
/opt/driver/pane-hook.sh "$id" \
    "{\"hook_event_name\":\"SessionStart\",\"transcript_path\":\"${new_jsonl_path}\"}" >/dev/null

state=$(agent-director get --claude-instance-id "$id" | jq -r '.state')
if [ "$state" != "waiting" ]; then
    echo "FAIL: state=$state; want waiting"; exit 1
fi
ended_after=$(sqlite3 "$HOME/.agent-director/state.db" \
    "SELECT IFNULL(ended_at,'') FROM spawns WHERE claude_instance_id='$id';")
if [ -n "$ended_after" ]; then
    echo "FAIL: ended_at=$ended_after; want empty (cleared on resurrection)"; exit 1
fi
echo "resume-8 ok: resurrection cleared ended_at; state=waiting"
```
