# relay-3: deny with empty reason defaults to "Denied by orchestrator"

Per SRD §6.3: on `deny` with empty reason, the envelope's message
field defaults to "Denied by orchestrator" so the TUI always shows
something actionable. The default lives at the envelope encoder
(not the DB). decide() stores the canonical reason "operator" for a
deny, so this case pins that stored reason (see the Script's note).

## Setup

Per-case DB-reset. Epic 8 (`t1.h98.xw`, SR-20.9, SR-22.9): a hook moves a
row only when it comes from the row's own pane process, so the row is a
real spawn and every hook is typed into its pane. The spawn runs with
`--relay-mode on` (which puts `AGENT_DIRECTOR_RELAY_MODE=on` in the
session's environment, so the pane's shell and the hook it forks inherit
it) and with `PATH=/opt/driver/stand-in-claude:$PATH` prefixed to the
`agent-director` command, so the pane process is the stand-in claude's
interactive bash. `/opt/driver/pane-hook.sh` types each hook into that
pane; the blocking PermissionRequest uses `--no-wait` (prints the job
dir) and `--wait <job dir>` (prints the hook's stdout, exits with the
hook's exit status). No hook is piped from the case's own shell, so the
driver shell backgrounds nothing. The session is named `cd-<case>` so
the DB-reset fixture's `cd-*` sweep removes it.

## Steps

1. `PATH=/opt/driver/stand-in-claude:$PATH agent-director spawn --cwd /tmp
   --relay-mode on --tmux-session-name cd-r3` → capture
   `claude_instance_id`.
2. Type a SessionStart hook into the pane → state `waiting`.
3. Type the PermissionRequest into the pane (`--no-wait`); poll the store
   for the open request's token.
4. `decide --decision=deny` (no --reason).
5. `pane-hook.sh --wait <job dir>`; the envelope's message is "operator".

## Pass criteria

- Hook exits 0.
- behavior=deny, message="operator".

## Script

```bash
set -euo pipefail
id="$(PATH="/opt/driver/stand-in-claude:$PATH" agent-director spawn --cwd /tmp --relay-mode on --tmux-session-name cd-r3 | jq -r '.claude_instance_id')"
test -n "$id"
# SR-22.9: the hooks are typed into the row's pane, so they apply.
/opt/driver/pane-hook.sh "$id" '{"hook_event_name":"SessionStart","transcript_path":"/x/r3.jsonl"}'
state="$(agent-director status --claude-instance-id "$id" | jq -r '.state')"
test "$state" = "waiting"

job="$(/opt/driver/pane-hook.sh --no-wait "$id" '{"hook_event_name":"PermissionRequest","tool_name":"Bash"}')"

# decide REQUIRES --request-token: read the token the hook in the pane
# minted for the open permission_requests row.
token=""
for _ in $(seq 1 50); do
    token=$(/opt/driver/sql.sh -readonly "$HOME/.agent-director/state.db" \
      "SELECT request_token FROM permission_requests
       WHERE claude_instance_id='$id' AND decision IS NULL
       ORDER BY request_id DESC LIMIT 1;")
    [ -n "$token" ] && break
    sleep 0.1
done
if [ -z "$token" ]; then
    echo "FAIL: no open permission_requests row for $id (hook never upserted)"; exit 1
fi

agent-director decide --claude-instance-id "$id" --request-token "$token" --decision deny >/dev/null

# --wait exits with the hook's exit status: set -e fails the case unless 0.
hook_out=$(mktemp)
/opt/driver/pane-hook.sh --wait "$job" >"$hook_out"
behavior=$(jq -r '.hookSpecificOutput.decision.behavior' "$hook_out")
message=$(jq -r '.hookSpecificOutput.decision.message' "$hook_out")

# The envelope's message mirrors the DB decision_reason (internal/hook/
# polling.go → EncodeDecision). Even with an EMPTY --reason, decide()
# persists the canonical store.DecisionReasonOperator ("operator") for a
# deny (pkg/api/decide.go). Because that reason is non-empty, EncodeDecision
# passes it straight through — the envelope message is "operator", NOT the
# empty-reason "Denied by orchestrator" fallback (which only the hook's own
# fail-closed/timeout deny path with a truly empty reason produces; see
# relay-8).
if [ "$behavior" != "deny" ] || [ "$message" != "operator" ]; then
    echo "FAIL: envelope behavior=$behavior message=$message; want deny/'operator'"
    cat "$hook_out"; exit 1
fi
echo "relay-3 ok: empty --reason deny still persists canonical 'operator'"
```
