# needs-intelligence

Shell testplan for the `needs_intelligence` Displayed State of an unanswered
permission request. The driver resets a binary-derived store before each
independent case and writes `[state] needs_intelligence_timeout_seconds =
3600`, a non-default value. No credentials, interactive agent or background
worker is needed, and no wall-clock wait supplies evidence: each case seeds
requests whose fallback clock is set relative to that timeout (most in 2020,
long past it; the public case's `public-recent` request 10 minutes before the
case start, within it), and the shipped binary does every observation. The only
wait is `guards`' bounded retry of its zero-wait `decide` while that refuses
`ErrStoreBusy` under load (every 100 ms, at most 10 s).

The cases cover, through public reads, refusals and the audit trail,
all-agent display with process-to-process continuation and the configured
timeout, representative continuity and report-only command guards. Expected
wire values come from the shared
`cmd/agent-director/testdata/display/needs_intelligence.json`. Every entry
writes exactly one `ad.spawn.displayed_state_transition` record to
`~/.config/agent-director/ad-trail.jsonl`; the DB reset leaves that file, so
each case reads only its own instance ids' records. Exact clock boundaries,
stale races, direct moves and settlement matrices stay unit tests. Each case
prints one compact JSON evidence line of observed values, with each `since`
printed as the facts asserted about it rather than its run-time timestamp,
so every passing run prints the same line (a case on a binary without the
v14 columns prints `availability: unavailable` and exits 77, never a pass).
The runnable driver is `test/driver/needs-intelligence.cjs`.
