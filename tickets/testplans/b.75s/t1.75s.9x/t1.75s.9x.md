# Epic 4 — `epic-04-interact` testplan

t1 collector for Epic 4 (`t1.8op.gm` — External interaction: send-keys
+ read-pane). Each t2 is a plain-English case the Docker harness
executes. The Epic 4 Progression Contract requires every t2 to pass
under `make test-docker EPIC=epic-04-interact` per the orchestrator's
first-hand audit.

## Sourced from

- Epic ticket: `t1.8op.gm` (Acceptance Criteria #1–#3).
- SRD §4.3 (send-keys multiline + `\r` strip), §12 (verb shapes).
- Reference notes: `send-keys-research.md`, `pane-output-research.md`.
- Epic 8 (`t1.h98.xw`, SR-20.9, SR-22.9, SR-14 `ad.hook.ignored`, PRD
  AC-HOOK-04): `interact-12` — a hook moves a row only when it comes
  from the row's own pane process.
- Epic 11 (`t1.h98.m6`; SR-3.4, SR-3.6, SR-7.1, SR-7.2, SR-18.14,
  SR-20.9, SR-22.8; PRD AC-PANE-08, AC-PANE-09, AC-DOC-14): the pane
  verbs reach a row's session only by its label and act on the agent's
  pane by pane id (the labelled seeding of interact-1, 2, 4, 5, 6, 8

  and `interact-11` (a resumed `pending` row and
  `send-keys --allow-pending`).

## Driver mode

All cases are written for `DRIVER_MODE=shell` — the orchestrator runs
the harness with `make test-docker EPIC=epic-04-interact`. Each t2 body
has a single fenced ` ```bash ` block the driver executes after the
per-case DB-reset fixture.

The harness uses the real `agent-director` binary (built by
`test-image`) plus the real `tmux` inside the Docker image. Cases
name their sessions under the `cd-` prefix so the per-case DB-reset's
session sweep cleans them between cases (except interact-12, whose
spawn takes the default name); interact-1, 2, 4, 5, 6 and 8 to 11 also
kill their sessions by session id (`$N`) in an EXIT trap. The pane
verbs reach a session only through its `@ad_owner` label, so the cases
that make sessions by hand (interact-1, 2, 4, 5, 6, 8, 9 and 10) label
them as described under "Label seeding"; interact-11 and interact-12
make their sessions with `agent-director spawn` / `resume`, which label
them themselves.

Cases that exercise CR-strip / multiline text inject it via the CLI
`--text` flag with literal `$'...'` (ANSI-C) quoting; bash passes the
resulting bytes through to agent-director, which strips CR and
preserves LF before invoking tmux send-keys on the agent's pane id. The
test then captures the real tmux pane via `read-pane` (and, where it
checks a pane directly, `tmux capture-pane -p -t <pane id>`), never by
a name target.

`interact-11` and `interact-12` spawn (and `interact-11` resumes) with
the stand-in claude: the `agent-director spawn` and `agent-director
resume` commands are prefixed with `PATH=/opt/driver/stand-in-claude:$PATH`
(tmux looks `claude` up on the launching process's PATH, so
`--extra-env PATH` does not select it, and a resume does not re-select
it through the row's extra environment), and the stand-in `exec`s an
interactive bash that is the row's recorded pane process. Hooks that
should apply are typed into that pane with `/opt/driver/pane-hook.sh
<id> '<payload>'`; `--pane <target>` types into another pane. A hook
piped from the case's own shell has the case's shell as its parent, so
the gate ignores it (`ad.hook.ignored`, `pid_mismatch`) — `interact-12`
does that on purpose; `interact-11` never does. The trail
(`~/.agent-director/ad-trail.jsonl`) is not wiped by the DB-reset, so
trail checks filter on the case's instance id.

`interact-11` keeps credentials out of its sessions (Epic 10 Task 4
pattern): before any tmux or agent-director call it unsets
`ANTHROPIC_API_KEY` and `CLAUDE_CODE_OAUTH_TOKEN` and removes them from
the tmux server's global environment (tolerating no server), and after
each spawn and the resume it checks neither appears in
`/proc/<recorded pane_pid>/environ`.

## Label seeding (pane-verb cases)

Since Epic 11 (`t1.h98.m6`, Tasks `t2.h98.m6.ki` and `t2.h98.m6.bh`;
SR-3.4, SR-3.6, SR-7.2, SR-20.9) `read-pane` and `send-keys` find a
row's session only by its `@ad_owner` label (one lookup, one pane
listing) and act on the agent's pane by pane id; an unlabelled `cd-*`
session is Gone to them (`ErrTmuxCaptureFailed`, `ErrTmuxSendKeys`).
The send-keys cases (interact-1, 2, 4, 8, 9), the read-pane cases
(interact-1, 2, 4, 5, 6, 9) and the holder's session in interact-10
therefore seed like kill-1 (`t2.75s.ks.3h`): the session is made with
`-e AGENT_DIRECTOR_INSTANCE_ID=<row id>` and its `$N` and pane id `%N`
are captured at creation; the row carries a 16-hex `launch_token` and
records no socket, server, pid or pane; the token and the store id
(`store_meta` `store_id`) are read back with `sqlite3`, never
hard-coded; the session gets the five-field
`ad1 <token> <$N> <row id> <store id>` as `@ad_owner`
(`set-option -t '<$N>'`) and the agent's pane gets `@ad_pane`
`<token> <%N>` (`set-option -p`), as agent-director's own create sets
them. With no pane recorded, both verbs find the agent's pane through
that `@ad_pane` (a raw pane without it gives "the agent's pane was not
found"). `send-keys` writes that adoption once (`row_version` advances
and the row records the pane id); `read-pane` writes nothing, so each
read-pane case checks `row_version` and `pane_id` are unchanged across
`read-pane`. interact-5 and interact-8 put an unlabelled decoy pane at
window 0 pane 0 (what `name:0.0` would hit) and split the agent's pane
off it, proving the verbs act by pane id. In interact-10 the label is
row B's, so row A (whose recorded name the session holds) is Gone and
nothing is adopted for it.

## Notes for the orchestrator

- Audit standard (SRD §17): run `make test-docker EPIC=epic-04-interact`
  yourself, inspect the JSON stream case-by-case, confirm each `t2`
  emitted `{"status":"pass"}`.
- The state-guard case `interact-7` synthesizes its `ended` row via a
  direct `sqlite3` insert after `db-reset` runs, with no session.
  `interact-8` seeds its `check_permission` row with `sqlite3` and a
  labelled session with `@ad_pane` (see "Label seeding"), so its relay
  refusal is not a missing session and its negative control delivers by
  pane id. `interact-10` seeds both rows with `sqlite3`.
- No real `claude` invocation is required for any case here;
  `interact-11` and `interact-12` launch only the stand-in claude, and
  `interact-11` also runs with the auth variables unset and kept out of
  its sessions.
- The `ErrSendKeysWhileRelayed` stub guard is active in Epic 4 even
  though the full relay path lands in Epic 10. The case here proves
  the precondition surface is correct from day one.

## tmux session sweep

Cases that exercise real tmux leave sessions under the `cd-*` prefix
(`interact-11` names its spawns `cd-i11x` and `cd-i11y`). The DB-reset
fixture kills `cd-*` sessions between cases.
