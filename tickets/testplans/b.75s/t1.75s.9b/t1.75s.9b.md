# Epic 8 — `epic-08-recovery` testplan

t1 collector for Epic 8 (`t1.8op.1w` — Crash recovery & DB hygiene:
find-missing + expire + delete). Each t2 is a plain-English case the
Docker harness executes. The Epic 8 Progression Contract requires
every t2 to pass under `make test-docker EPIC=epic-08-recovery`.

## Cases

| case | what it pins |
|---|---|
| `recov-1-find-missing-reconciles-killed` | spawn two Claudes; `tmux kill-session` externally on one and wait for its recorded pane process to exit; `find-missing` runs in a bounded loop (120 s, 3 s apart; a `pending` row inside its grace period, measured from the launch start, is correctly not judged) until it reports count=1 for the killed id, never listing the survivor; the killed row's state is now `missing` with `ended_at` populated. |
| `recov-2-find-missing-no-identity-tmux-lookup` | seed three live rows with `sqlite3` recording no process identity, token or socket (`waiting`; `pending` with a launch start past the grace period; `working`); two recorded names no session holds, one held by a hand-made unlabelled session → one `find-missing` returns `count=3`: the first two marked `missing` with tick reason `tmux_absent`, the third with `tmux_name_held` and exactly one `ad.launch.name_held` (source `ad_find_missing`); the holding session still runs, unlabelled. |
| `recov-3-find-missing-noop-when-all-alive` | spawn 2 Claudes; `find-missing` returns count=0, no state changes. |
| `recov-4-expire-zero-reaps-all-terminal` | seed terminal-state rows + live row → `expire --older-than 0d` removes only the terminal rows, returns their IDs. |
| `recov-5-expire-default-window-spares-young` | seed a terminal row with a fresh `ended_at` → `expire` (default 31d) returns count=0; the row survives. |
| `recov-6-delete-per-row-result-map` | seed two rows + one bogus id → `agent-director delete` is `ErrUnknownVerb` and removes nothing; `/opt/bin/agent-director-admin delete --claude-instance-id A --claude-instance-id A2 --claude-instance-id bogus` returns `{A:ok, A2:ok, bogus:ErrSpawnNotFound}`; A and A2 are gone. |
| `recov-7-delete-bypasses-state-guards` | seed live-state row → `/opt/bin/agent-director-admin delete --claude-instance-id <id>` returns `{<id>:ok}` and the row is gone; no tmux interaction asserted. |
| `recov-8-expire-keeps-row-whose-own-session-runs` | seed two `ended` rows with no process identity; label a hand-made `cd-` session as one row's own (five-field `@ad_owner` with this store's id read from `store_meta`) → `expire --older-than 0d` returns `count=1`/`ids=[session-less row]` and `kept=1`/`kept_ids=[labelled row]` with one `ad.expire.kept` (reason `ours`); the session still runs; after the case ends that session, the next `expire --older-than 0d` deletes the formerly kept row. |

## Driver mode

All cases are written for `DRIVER_MODE=shell` — the orchestrator runs
the harness with `make test-docker EPIC=epic-08-recovery`. Each t2
body has a single fenced ` ```bash ` block the driver executes after
the per-case DB-reset fixture.

The find-missing cases (1, 2, 3) exercise the real judgement:
`find-missing` judges a live row by its agent process (the SessionStart
pid, or else the pane process recorded at launch, each checked with its
start time), and a row whose process cannot be checked (none recorded,
or unreadable) is decided by one tmux lookup on the row's socket.
Case 1 uses the full spawn pipeline so a real tmux session + claude
process exist; the test then kills the session via `tmux kill-session`
(the operator's externally-driven kill path, NOT `agent-director
kill`), waits for the killed row's pane process to exit, and runs
`find-missing` in a bounded loop: the image's `claude` never reports
in, so both rows stay `pending`, and `find-missing` correctly leaves a
`pending` row alone while it is inside `pending_grace_seconds` (60 s by
default) of its launch start. The loop's 120 s bound exceeds that
default plus margin; any run that lists the survivor fails at once.
Case 2 seeds live rows directly via `sqlite3` with no process identity,
no launch token and no `tmux_socket`, so each is decided by the lookup
on the caller's socket: names no session holds are marked `missing`
(`tmux_absent`), and a name a hand-made session holds is marked
`missing` (`tmux_name_held`) while that session is left running. Case 3
spawns two Claudes and confirms `find-missing` doesn't false-positive
on rows whose pane processes still run.

The expire and delete cases (4 to 8) seed rows directly via `sqlite3`
for speed and isolation. `delete` (cases 6, 7; the operator tool
agent-director-admin's verb since b.vqr, run by its full path in the
harness image, `/opt/bin/agent-director-admin`) is pure DB cleanup and
makes no tmux call. `expire` (cases 4, 5, 8) does read tmux: for each
selected finished row it checks the row's agent process, and a row with
no recorded process identity is decided by one tmux lookup on the row's
socket (the caller's resolved socket when the row records none). Only a
row the lookup finds Gone is deleted; a row whose own labelled session
runs is kept with reason `ours` and listed in `kept_ids`. Cases 4 and 5
seed rows that no session holds, so their lookups read Gone and their
results are unchanged. Case 8 labels a session as one row's own and
checks that `expire` keeps that row, deletes the session-less one, and
deletes the kept row on the next run once its session has ended.

## Notes for the orchestrator

- Audit standard (SRD §17): run `make test-docker EPIC=epic-08-recovery`
  yourself, inspect the JSON stream case-by-case.
- The no-identity case (2) seeds rows via raw INSERT (no pid,
  proc_starttime, launch token, socket or pane), as rows from before the
  release look, and spawns nothing, so only the tmux lookup can decide
  them. Its ids and names are random per run and its seed first deletes
  rows an earlier run of the case left, so the harness's `bash -x`
  re-run of a failed case starts clean. It selects trail records by its
  own ids, since the trail is not reset between cases.
- Case 3's freshly spawned rows are `pending` and inside the grace
  period when it runs `find-missing`, so its `count=0` holds because
  those rows are not judged yet; were they judged, their pane processes
  still run.
- The `tmux kill-session` in case 1 is the EXTERNAL kill path (the
  operator typing it manually), distinct from `agent-director kill`
  which the kill_cli tests already cover. find-missing's job is to
  reconcile both paths the same way.

## tmux session sweep

Cases 1 and 3 launch real `agent-director spawn`; case 2 makes one
session by hand (`cd-rc2h-<n>`) and kills it on exit; case 8 makes one
labelled session by hand (`cd-rc8k-<n>`), ends it itself in its last
step, and also kills it on exit. The `cd-*`
prefix matches the DB-reset fixture's sweep so cases don't leak
sessions to each other.
