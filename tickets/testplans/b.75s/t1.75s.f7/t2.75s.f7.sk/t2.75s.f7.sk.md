# install-13: the find-missing / expire schedule (b.wur)

Before b.wur nothing in the install skill or install.sh set up, or even
mentioned, the two sweeps that keep the row states honest: `find-missing`
(marks a row whose agent is gone `missing`) and `expire` (deletes finished
rows). This case pins the three things the fix adds, end to end, against the
image's bundled install script and binary:

1. A fresh install with no schedule ends with a loud WARNING on stderr, after
   the `install.sh: done.` line, naming the crontab lines. The exit status
   stays 0.
2. `install.sh --schedule` adds this install's `find-missing` and `expire`
   lines to the user's crontab, tagged `agent-director-schedule`, keeps the
   user's own lines, is idempotent, and ends with no warning; `uninstall.sh`
   removes exactly the tagged lines.
3. The acceptance criterion: a killed agent's row is marked `missing` by the
   scheduled run, with no manual `find-missing`. The case takes the installed
   crontab line, drops its five time fields and runs the rest the way cron
   does (`/bin/sh -c`, an empty environment but HOME, LOGNAME, SHELL and a
   minimal PATH), until the killed row's state is `missing` and the survivor's
   is not.

The image has no cron daemon and no `crontab` program, and no systemd. The
case therefore gives install.sh a stand-in `crontab` through its test-only
`INSTALL_SH_TEST_CRONTAB` switch (the stand-in keeps the crontab in a file),
points `INSTALL_SH_TEST_SYSTEMCTL` at nothing so no other mechanism can answer,
and plays the cron daemon's part itself. install.sh uses cron only when a cron
daemon runs, and the image runs none, so the case says so two ways:

- Step 2 runs `--schedule` with the image's real answer (no
  `INSTALL_SH_TEST_CRON_RUNNING`, so install.sh looks for a process named
  `cron` or `crond` and finds none) and pins what it does with no daemon and
  no systemd: the crontab lines go in anyway, stderr says NO CRON DAEMON, and
  the warning says why.
- Every other install.sh run sets `INSTALL_SH_TEST_CRON_RUNNING=1`, standing
  in for a cron daemon that runs, so the cron path under test is the real one.

`INSTALL_SH_TEST_PASSWD_HOME` is set to the case's HOME on every run, so the
HOME the case gives is the passwd home and install.sh does not write a `HOME=`
word into the crontab lines (the lines it writes are the ones cron's own HOME
makes right). The scheduled run's own environment, in step 6, still gives HOME, as cron does.

### Why the scheduled run is repeated for up to 120 s

`find-missing` never judges a `pending` row inside the pending grace period
(`pending_grace_seconds`, 60 s by default, from `launch_started_at`; see
`recov-1`). The stand-in `claude` (`/opt/driver/stand-in-claude`) reports no
hook, so both rows stay `pending`. The case runs the crontab's command every
3 s, exactly as cron would every 2 minutes, until the killed row is `missing`
or 120 s have passed. It never runs `agent-director find-missing` itself.

## Setup

Per-case DB-reset. A fresh `$HOME` of its own holds the install and the store
this case reads and writes; the survivor and killed rows are spawned from the
installed binary with that HOME.

## Steps

1. Fresh install with no `--schedule`, stdout and stderr in one file. Exit 0;
   the file holds `install.sh: done.` followed by the line
   `install.sh: WARNING: nothing schedules agent-director's find-missing and
   expire sweeps`, the two crontab lines the warning prints naming the
   installed binary, and the command that repeats the install with
   `--schedule`, which starts `cd <the directory the install ran in> && bash
   <the script>`. The stand-in crontab was never written.
2. No cron daemon runs in the image (checked). Run `install.sh --schedule`
   with no daemon seam, stdout and stderr in separate files. Exit 0; stderr
   holds the `NO CRON DAEMON` line and a WARNING whose reason is that no cron
   daemon runs, so the crontab lines just added do not run; the crontab
   holds the two tagged lines anyway. Remove the stand-in crontab again.
3. Seed the stand-in crontab with two user lines. Run `install.sh --schedule`
   with the daemon seam on. Exit 0, no WARNING; the crontab holds the user's
   lines unchanged and in place, and one `find-missing` and one `expire` line
   each ending `# agent-director-schedule`, naming the installed binary and
   with no `HOME=` word.
4. Run `install.sh --schedule` again: exit 0, no WARNING, the crontab is
   byte for byte the same.
5. Spawn two agents with the installed binary (stand-in `claude` first on
   PATH). Kill the first one's tmux session (the manual path, not
   `agent-director kill`) and wait for its pane process to exit.
6. Take the `find-missing` line from the crontab, drop its five time fields
   and run the rest under `env -i HOME=... LOGNAME=... SHELL=/bin/sh
   PATH=/usr/bin:/bin /bin/sh -c`, every 3 s for up to 120 s. Every run exits
   0. Stop at the first run after which the killed row is `missing` (read
   with `agent-director get`).
7. The killed row is `missing` with `ended_at` set; the survivor is not
   `missing`.
8. Run the `expire` line the same way. Exit 0; the killed row's `ended_at` is
   seconds old, inside the retention window, so both rows are still there.
   Back-date the killed row's `ended_at` 400 days (past the default
   `expire_retention_days`), run the `expire` line again: exit 0, the killed
   row is gone and the survivor's row is still there.
9. Run `uninstall.sh`: the crontab is left with the user's two lines only;
   no line carries the marker.

Every `install.sh` and `uninstall.sh` run is checked for its exit status in a
way that prints a FAIL line and the run's output before the case ends (under
`set -e` a bare failing command would end the case with no message).

## Pass criteria

- Step 1: exit 0; the WARNING follows the done line; the re-run command it
  prints starts `cd <dir> && bash <script>` and ends `--schedule`; the
  stand-in crontab was not written.
- Step 2: exit 0; `NO CRON DAEMON` on stderr; the warning names the missing
  daemon; the two tagged lines are in the crontab.
- Step 3: no WARNING; user lines kept; exactly one tagged `find-missing` and
  one tagged `expire` line naming the installed binary, with no `HOME=`.
- Step 4: the crontab is unchanged.
- Steps 6 and 7: the scheduled command marks the killed row `missing` within
  120 s, with no `agent-director find-missing` typed by the case, and never
  marks the survivor.
- Step 8: the scheduled `expire` keeps a row inside the retention window,
  deletes the back-dated finished row and keeps the live survivor's row.
- Step 9: the crontab equals the user's seeded lines.

## Script

```bash
set -euo pipefail

TESTHOME=$(mktemp -d)
MARK="agent-director-schedule"
INSTALL=/opt/skills/install-agent-director/install.sh
UNINSTALL=/opt/skills/install-agent-director/uninstall.sh
CANONICAL="$TESTHOME/.config/agent-director/bin/agent-director"
DB="$TESTHOME/.config/agent-director/state.db"

# The stand-in crontab: the user's crontab is the file $CRON_STUB_FILE; no
# file means no crontab yet, which `crontab -l` reports as the real one does.
mkdir -p "$TESTHOME/stub-bin"
cat > "$TESTHOME/stub-bin/crontab" <<'EOF'
#!/usr/bin/env bash
case "$1" in
-l)
    [[ -f "$CRON_STUB_FILE" ]] || { echo "no crontab for $(id -un)" >&2; exit 1; }
    cat "$CRON_STUB_FILE" ;;
-)  cat > "$CRON_STUB_FILE" ;;
-r) rm -f "$CRON_STUB_FILE" ;;
*)  echo "usage: crontab [-l | - | -r]" >&2; exit 2 ;;
esac
EOF
chmod +x "$TESTHOME/stub-bin/crontab"
export CRON_STUB_FILE="$TESTHOME/crontab.txt"

# The seams and HOME for every install.sh and uninstall.sh run of the case.
# No systemctl answers, so cron is the only mechanism. HOME is the passwd home
# (INSTALL_SH_TEST_PASSWD_HOME), so install.sh writes no HOME= word.
# Arguments: NAME=value words for the environment, then the command.
run_script_env() {
    env HOME="$TESTHOME" \
        INSTALL_SH_TEST_PASSWD_HOME="$TESTHOME" \
        INSTALL_SH_TEST_CRONTAB="$TESTHOME/stub-bin/crontab" \
        INSTALL_SH_TEST_SYSTEMCTL="$TESTHOME/no-such-systemctl" \
        "$@"
}
# The image's own answer to "does a cron daemon run": install.sh looks for one.
run_script_autodetect() {
    run_script_env "$@"
}
# The same, standing in for a cron daemon that runs.
run_script() {
    run_script_env INSTALL_SH_TEST_CRON_RUNNING=1 "$@"
}

# The Docker image runs no cron daemon; step 2 depends on it.
if pgrep -x cron >/dev/null || pgrep -x crond >/dev/null; then
    echo "FAIL: a cron daemon runs in this image; step 2 needs none"; exit 1
fi

# Both sessions are killed whatever happens.
survivor_sess=""
killed_sess=""
cleanup() {
    for s in "$killed_sess" "$survivor_sess"; do
        [ -n "$s" ] && tmux kill-session -t "$s" 2>/dev/null || true
    done
}
trap cleanup EXIT

# --- 1. A fresh install with no schedule ends with the warning --------------
set +e
run_script "$INSTALL" --binary /usr/local/bin/agent-director --no-symlink \
    >"$TESTHOME/fresh.out" 2>&1
rc=$?
set -e
if [ "$rc" != "0" ]; then
    echo "FAIL: fresh install exit=$rc; want 0 (the warning never changes the exit status)"
    cat "$TESTHOME/fresh.out"; exit 1
fi
# grep finding nothing must reach the FAIL below, not end the case under
# `set -e` with pipefail: hence the `|| true`.
done_line=$(grep -n '^install\.sh: done\.' "$TESTHOME/fresh.out" | head -1 | cut -d: -f1 || true)
warn_line=$(grep -n "^install\.sh: WARNING: nothing schedules agent-director's find-missing and expire sweeps" \
    "$TESTHOME/fresh.out" | head -1 | cut -d: -f1 || true)
if [ -z "$done_line" ]; then
    echo "FAIL: no 'install.sh: done.' line"; cat "$TESTHOME/fresh.out"; exit 1
fi
if [ -z "$warn_line" ]; then
    echo "FAIL: a fresh install with no schedule printed no WARNING"; cat "$TESTHOME/fresh.out"; exit 1
fi
if [ "$warn_line" -le "$done_line" ]; then
    echo "FAIL: the WARNING (line $warn_line) does not follow the done line ($done_line)"
    cat "$TESTHOME/fresh.out"; exit 1
fi
# The warning names the lines to add, with this install's binary, and the way
# to have the script add them.
for want in \
    "$CANONICAL find-missing" \
    "$CANONICAL expire" \
    "# $MARK" \
    "--schedule"; do
    if ! sed -n "${warn_line},\$p" "$TESTHOME/fresh.out" | grep -qF -- "$want"; then
        echo "FAIL: the warning does not mention: $want"
        sed -n "${warn_line},\$p" "$TESTHOME/fresh.out"; exit 1
    fi
done
# The re-run command starts with the directory the install ran in, so that it
# repeats the same install from anywhere (a relative path and --register-mcp
# depend on it), and carries the script, then --schedule.
if ! sed -n "${warn_line},\$p" "$TESTHOME/fresh.out" \
    | grep -qE '^    cd .+ && bash [^ ]*install\.sh .*--schedule$'; then
    echo "FAIL: the warning's re-run command is not 'cd <dir> && bash <script> ... --schedule':"
    sed -n "${warn_line},\$p" "$TESTHOME/fresh.out"; exit 1
fi
if [ -e "$CRON_STUB_FILE" ]; then
    echo "FAIL: an install without --schedule wrote a crontab:"; cat "$CRON_STUB_FILE"; exit 1
fi

# --- 2. --schedule with no cron daemon: lines in, loud about it -------------
# No INSTALL_SH_TEST_CRON_RUNNING: install.sh looks for a process named cron
# or crond, as it does on a real machine, and the image has none. With no
# systemd either, the crontab lines are put in anyway and stderr says so.
if ! run_script_autodetect "$INSTALL" --binary /usr/local/bin/agent-director --no-symlink --schedule \
    >"$TESTHOME/nodaemon.out" 2>"$TESTHOME/nodaemon.err"; then
    echo "FAIL: --schedule with no cron daemon did not exit 0"
    cat "$TESTHOME/nodaemon.err"; exit 1
fi
if ! grep -qF 'but NO CRON DAEMON (a process named cron or crond) is running on this machine, so they do not run' \
    "$TESTHOME/nodaemon.err"; then
    echo "FAIL: stderr has no NO CRON DAEMON line:"; cat "$TESTHOME/nodaemon.err"; exit 1
fi
if ! grep -qF 'WARNING' "$TESTHOME/nodaemon.err" \
    || ! grep -qF 'no cron daemon (a process named cron or crond) is running on this machine, so the crontab lines just added do not run' \
        "$TESTHOME/nodaemon.err"; then
    echo "FAIL: the warning does not say no cron daemon runs:"; cat "$TESTHOME/nodaemon.err"; exit 1
fi
if [ ! -f "$CRON_STUB_FILE" ] \
    || [ "$(grep -c "# $MARK\$" "$CRON_STUB_FILE" || true)" != "2" ]; then
    echo "FAIL: the crontab does not hold the two tagged lines:"; cat "$CRON_STUB_FILE" || true; exit 1
fi
rm -f "$CRON_STUB_FILE"

# --- 3. --schedule adds the entries, keeps the user's lines ----------------
printf '%s\n' 'MAILTO=me@example.com' '0 * * * * /usr/bin/other-job' > "$CRON_STUB_FILE"
cp "$CRON_STUB_FILE" "$TESTHOME/crontab.seed"

if ! run_script "$INSTALL" --binary /usr/local/bin/agent-director --no-symlink --schedule \
    >"$TESTHOME/sched.out" 2>"$TESTHOME/sched.err"; then
    echo "FAIL: install.sh --schedule did not exit 0"
    cat "$TESTHOME/sched.out" "$TESTHOME/sched.err"; exit 1
fi
if grep -q 'WARNING' "$TESTHOME/sched.err" "$TESTHOME/sched.out"; then
    echo "FAIL: --schedule still warned:"; cat "$TESTHOME/sched.err"; exit 1
fi
if ! grep -q '^  schedule: cron: .*added to this user' "$TESTHOME/sched.out"; then
    echo "FAIL: stdout has no 'schedule: cron: ... added' line:"; cat "$TESTHOME/sched.out"; exit 1
fi
# The user's two lines are first, unchanged and in place.
if ! head -n 2 "$CRON_STUB_FILE" | cmp -s - "$TESTHOME/crontab.seed"; then
    echo "FAIL: the user's own crontab lines changed:"; cat "$CRON_STUB_FILE"; exit 1
fi
fm_lines=$(grep -v '^#' "$CRON_STUB_FILE" | grep -cE " $CANONICAL find-missing >/dev/null # $MARK\$" || true)
ex_lines=$(grep -v '^#' "$CRON_STUB_FILE" | grep -cE " $CANONICAL expire >/dev/null # $MARK\$" || true)
if [ "$fm_lines" != "1" ] || [ "$ex_lines" != "1" ]; then
    echo "FAIL: crontab holds $fm_lines find-missing and $ex_lines expire lines for this install; want 1 and 1"
    cat "$CRON_STUB_FILE"; exit 1
fi
# HOME is the passwd home here (the seam), so no HOME= word is written.
if grep -v '^#' "$CRON_STUB_FILE" | grep -q ' HOME='; then
    echo "FAIL: a crontab line carries a HOME= word though HOME is the passwd home:"
    cat "$CRON_STUB_FILE"; exit 1
fi

# --- 4. A re-run changes nothing --------------------------------------------
cp "$CRON_STUB_FILE" "$TESTHOME/crontab.after-first"
if ! run_script "$INSTALL" --binary /usr/local/bin/agent-director --no-symlink --schedule \
    >"$TESTHOME/sched2.out" 2>"$TESTHOME/sched2.err"; then
    echo "FAIL: the --schedule re-run did not exit 0"
    cat "$TESTHOME/sched2.out" "$TESTHOME/sched2.err"; exit 1
fi
if grep -q 'WARNING' "$TESTHOME/sched2.err" "$TESTHOME/sched2.out"; then
    echo "FAIL: the --schedule re-run warned:"; cat "$TESTHOME/sched2.err"; exit 1
fi
if ! cmp -s "$CRON_STUB_FILE" "$TESTHOME/crontab.after-first"; then
    echo "FAIL: the --schedule re-run changed the crontab:"
    diff "$TESTHOME/crontab.after-first" "$CRON_STUB_FILE" || true; exit 1
fi

# --- 5. Two agents; the first is killed from outside ------------------------
killed=$(HOME="$TESTHOME" PATH="/opt/driver/stand-in-claude:$PATH" \
    "$CANONICAL" spawn --agent claude --cwd /tmp | jq -r '.instance_id')
survivor=$(HOME="$TESTHOME" PATH="/opt/driver/stand-in-claude:$PATH" \
    "$CANONICAL" spawn --agent claude --cwd /tmp | jq -r '.instance_id')
# `test ... && test ...` under set -e never ends the case when the first test
# fails, so each check is its own if.
if [ -z "$killed" ] || [ -z "$survivor" ]; then
    echo "FAIL: spawn returned no instance id (killed='$killed' survivor='$survivor')"; exit 1
fi
killed_sess=$(HOME="$TESTHOME" "$CANONICAL" get --instance-id "$killed" | jq -r '.tmux_session_name')
survivor_sess=$(HOME="$TESTHOME" "$CANONICAL" get --instance-id "$survivor" | jq -r '.tmux_session_name')
if [ -z "$killed_sess" ] || [ -z "$survivor_sess" ]; then
    echo "FAIL: no tmux session name (killed='$killed_sess' survivor='$survivor_sess')"; exit 1
fi

pane_pid=$(/opt/driver/sql.sh "$DB" "SELECT pane_pid FROM spawns WHERE instance_id='$killed';")
if [ -z "$pane_pid" ] || ! kill -0 "$pane_pid" 2>/dev/null; then
    echo "FAIL: killed row's pane process ('$pane_pid') is not running before the kill"; exit 1
fi
tmux kill-session -t "$killed_sess"
deadline=$(( $(date +%s) + 10 ))
while kill -0 "$pane_pid" 2>/dev/null && [ "$(date +%s)" -lt "$deadline" ]; do
    sleep 0.2
done
if kill -0 "$pane_pid" 2>/dev/null; then
    echo "FAIL: pane process $pane_pid still runs 10s after kill-session"; exit 1
fi

# --- 6. Run the crontab's own command, as cron does -------------------------
# cron_cmd NAME prints the command of the crontab line for NAME: the line
# without its five time fields. No such line prints nothing (the `|| true`
# keeps pipefail from ending the case before the FAIL below).
cron_cmd() {
    { grep -v '^#' "$CRON_STUB_FILE" | grep -E " $CANONICAL $1 " | head -1 \
        | sed -E 's/^([^ ]+[ ]+){5}//'; } || true
}
# cron_run runs a command the way cron runs a job: /bin/sh -c, an environment
# of HOME, LOGNAME, SHELL and a minimal PATH, nothing else. A failing command
# prints its FAIL line here and ends the case.
cron_run() {
    if ! env -i HOME="$TESTHOME" LOGNAME="$(id -un)" SHELL=/bin/sh PATH=/usr/bin:/bin \
        /bin/sh -c "$1"; then
        echo "FAIL: the scheduled command exited non-zero: $1"; exit 1
    fi
}
fm_cmd=$(cron_cmd find-missing)
ex_cmd=$(cron_cmd expire)
if [ -z "$fm_cmd" ] || [ -z "$ex_cmd" ]; then
    echo "FAIL: no find-missing or expire command in the crontab"; cat "$CRON_STUB_FILE"; exit 1
fi

# The survivor and killed rows are pending, so find-missing leaves the killed
# row alone until its grace period (60 s by default) has passed: repeat the
# scheduled command, as cron would, until the state flips or 120 s pass.
start=$(date +%s)
deadline=$(( start + 120 ))
runs=0
state=""
while [ "$(date +%s)" -lt "$deadline" ]; do
    cron_run "$fm_cmd"
    runs=$(( runs + 1 ))
    state=$(HOME="$TESTHOME" "$CANONICAL" get --instance-id "$killed" | jq -r '.state' || echo "get-failed")
    [ "$state" = "missing" ] && break
    sleep 3
done
if [ "$state" != "missing" ]; then
    echo "FAIL: the scheduled find-missing never marked the killed row missing in 120s ($runs runs; state=$state)"
    HOME="$TESTHOME" "$CANONICAL" get --instance-id "$killed" \
        | jq -r '"launch_started_at=\(.launch_started_at // "absent")"' || true
    exit 1
fi

# --- 7. The killed row is missing; the survivor is not ----------------------
ended=$(/opt/driver/sql.sh "$DB" "SELECT ended_at FROM spawns WHERE instance_id='$killed';")
if [ -z "$ended" ]; then
    echo "FAIL: ended_at not populated on the row the scheduled find-missing marked"; exit 1
fi
survivor_state=$(HOME="$TESTHOME" "$CANONICAL" get --instance-id "$survivor" | jq -r '.state')
if [ "$survivor_state" = "missing" ]; then
    echo "FAIL: the scheduled find-missing marked the live survivor missing"; exit 1
fi

# --- 8. The scheduled expire: keeps a recent row, deletes an old one --------
# row_count ID prints how many rows the store holds for ID.
row_count() {
    /opt/driver/sql.sh "$DB" "SELECT count(*) FROM spawns WHERE instance_id='$1';"
}
# ended_at is seconds old: inside expire_retention_days, so nothing goes.
cron_run "$ex_cmd"
if [ "$(row_count "$killed")" != "1" ]; then
    echo "FAIL: the scheduled expire removed a finished row still inside the retention window"; exit 1
fi
# Back-date ended_at, in the store's own layout, past any default window.
/opt/driver/sql.sh "$DB" "UPDATE spawns SET ended_at = datetime('now', '-400 days') WHERE instance_id='$killed';"
cron_run "$ex_cmd"
if [ "$(row_count "$killed")" != "0" ]; then
    echo "FAIL: the scheduled expire left the finished row ended 400 days ago"; exit 1
fi
if [ "$(row_count "$survivor")" != "1" ]; then
    echo "FAIL: the scheduled expire removed the live survivor's row"; exit 1
fi

# --- 9. uninstall.sh removes exactly the tagged lines -----------------------
if ! run_script "$UNINSTALL" >"$TESTHOME/uninstall.out" 2>&1; then
    echo "FAIL: uninstall.sh did not exit 0"; cat "$TESTHOME/uninstall.out"; exit 1
fi
if grep -q "$MARK" "$CRON_STUB_FILE" 2>/dev/null; then
    echo "FAIL: a line tagged $MARK is left after uninstall:"; cat "$CRON_STUB_FILE"; exit 1
fi
if ! cmp -s "$CRON_STUB_FILE" "$TESTHOME/crontab.seed"; then
    echo "FAIL: the crontab is not the user's own lines after uninstall:"; cat "$CRON_STUB_FILE"; exit 1
fi

echo "install-13 ok: fresh install warns; --schedule with no daemon warns loudly; with one it adds 2 tagged lines, idempotent, user lines kept; the scheduled run marked the killed row missing (run $runs, $(( $(date +%s) - start ))s) and spared the survivor; the scheduled expire kept a recent row and deleted an old one; uninstall removed the lines"
```
