# Epic 10 — `epic-10-relay` testplan

t1 collector for Epic 10 (`t1.8op.g8` — Permission relay). Each t2
is a plain-English case the Docker harness executes. The Epic 10
Progression Contract requires every t2 to pass under
`make test-docker EPIC=epic-10-relay`.

## Sourced from

- Epic ticket: `t1.8op.g8` (Acceptance Criteria #1–#4).
- Epic 8 `t1.h98.xw` (hook gate): SRD SR-20.9 (synthesised hooks are
  typed into the row's pane), SR-22.9 (a hook moves a row, and a relayed
  PermissionRequest records a request, only when its parent is the row's
  recorded pane process). Build-lead decision A6 rebuilds relay-1, 2, 3,
  4 and 8 on that pattern.
- SRD §6.2 (relay polling), §6.3 (envelope wire shape), §6.4
  (fail-closed boundary), §6.5 (env-var read of relay mode), §12
  (decide verb), §13.1 (error catalogue).

## Cases

| case | what it pins |
|---|---|
| `relay-1-allow-roundtrip` | spawn relay=on (stand-in claude) + PermissionRequest typed into the row's pane (polling) + `decide --decision=allow --reason "ok"` → hook's stdout carries the allow envelope. |
| `relay-2-deny-with-reason` | same shape, decision=deny with a reason → deny envelope carrying the canonical stored reason `operator`. |
| `relay-3-deny-default-message` | same shape, decide deny with empty reason → envelope's message is the canonical stored reason `operator` (the "Denied by orchestrator" fallback is the hook's own empty-reason deny). |
| `relay-4-already-decided` | same shape; first decide writes; second decide on the same instance id and token → ErrAlreadyDecided. |
| `relay-5-relay-mode-off` | spawn relay_mode=off; `decide` → ErrRelayModeOff (no envelope, no DB write). |
| `relay-6-no-open-request` | spawn relay_mode=on but no PermissionRequest hook running → decide → ErrNoOpenPermissionRequest. |
| `relay-7-send-keys-while-relayed` | spawn relay_mode=on, state=check_permission, `send-keys` → ErrSendKeysWhileRelayed (Epic 4's stubbed guard, now active). |
| `relay-8-fail-closed-timeout` | same shape with `relay.timeout_seconds = 5`; no decide arrives → fail-closed deny envelope after ~2s (the poll ends 3s before the hook's kill instant, b.146 rule 4). |

## Driver mode

All cases are written for `DRIVER_MODE=shell` — the orchestrator runs
the harness with `make test-docker EPIC=epic-10-relay`. Each t2
body has a single fenced ` ```bash ` block the driver executes after
the per-case DB-reset fixture.

The hook cases (`relay-1`, `relay-2`, `relay-3`, `relay-4`, `relay-8`)
mock the Claude Code → hook-handler boundary with a synthesized
PermissionRequest payload rather than a real Claude. A hook moves a row,
and a relayed PermissionRequest records a request, only when the
`agent-director hook` process is a direct child of the row's recorded
pane process (SR-22.9); a hook piped from the case's own shell is
ignored as `pid_mismatch` and returns no decision. So (SR-20.9):

- The row is a real spawn: `PATH=/opt/driver/stand-in-claude:$PATH
  agent-director spawn --cwd /tmp --relay-mode on --tmux-session-name
  cd-<case>`. tmux looks `claude` up on the PATH of the process that
  runs the create (it replaces the session's PATH with the client's, so
  `--extra-env PATH=…` would still start the real Claude Code), and finds
  the stand-in `claude` (`test/driver/stand-in-claude/claude`) first; it
  ignores its arguments and `exec`s `bash --noprofile --norc -i`, so an
  interactive shell is the pane process agent-director records.
  `--relay-mode on` puts `AGENT_DIRECTOR_RELAY_MODE=on` in the session's
  environment, so the hook the pane's shell forks runs the relay path.
- Each case first types a SessionStart into the pane
  (`/opt/driver/pane-hook.sh <id> '<payload>'`), which turns the row
  `waiting` (the state the earlier sqlite3 seed wrote).
- The PermissionRequest blocks until `decide` (or the timeout), so it is
  typed with `/opt/driver/pane-hook.sh --no-wait <id> '<payload>'`, which
  prints a job dir and returns. The case polls the store (read-only
  `sqlite3`) for the open request's token, runs `decide` from the
  driver's shell (or doesn't, for the fail-closed case), then
  `/opt/driver/pane-hook.sh --wait <job dir>` prints the hook's stdout
  (the envelope) and exits with the hook's exit status.
- `pane-hook.sh` (`test/driver/pane-hook.sh`) reads the row's `pane_id`
  and `tmux_socket` with a read-only `sqlite3` SELECT and types
  `agent-director hook < <file> > <out> 2> <err>; echo $? > <rc>` into
  the pane with `tmux send-keys -l --` and Enter: simple commands, so the
  pane's bash forks the hook directly.

The hook's gated state write turns the row to state=check_permission;
the relay-side gated INSERT writes the permission_requests row that
`decide` updates.

The no-hook cases (`relay-5`, `relay-6`, `relay-7`) still seed their
rows directly with sqlite3: they run no hook, so the gate does not
apply to them.

## Notes for the orchestrator

- Audit standard (SRD §17): run `make test-docker EPIC=epic-10-relay`
  yourself, inspect the JSON stream case-by-case.
- The polling cadence floor is 50ms (SRD §6.2). Before invoking
  `decide`, the hook cases poll the store (up to 5s, every 100ms) for
  the open request's token, which also shows the hook in the pane has
  inserted its request.
- `relay-8-fail-closed-timeout` uses a 5-second `relay.timeout_seconds`
  override via a per-case `~/.agent-director/config.toml` (written
  before the spawn, read by the hook in the pane, removed by the case's
  EXIT trap) so the full harness runs in under a minute. The hook's
  poll ends 3s before its kill instant (b.146 rule 4: a 2s reserve
  for the ack plus 1s for the timeout deny's lock wait), so the deny
  comes ~2s after the hook starts. A timeout of 3s or less leaves no
  poll: the hook records its request but never acks and exits silently.

## tmux session sweep

The hook cases (`relay-1`, `relay-2`, `relay-3`, `relay-4`, `relay-8`)
spawn a session named `cd-r<n>`. The DB-reset fixture kills `cd-*`
sessions between cases (see `test/driver/db-reset.sh`), which also
ends a PermissionRequest hook still polling in a pane after a failed
case. The no-hook cases (`relay-5`, `relay-6`, `relay-7`) seed rows
directly via sqlite3 and create no tmux session.
