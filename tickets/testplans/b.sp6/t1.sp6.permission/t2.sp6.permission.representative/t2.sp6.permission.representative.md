# Independent requests preserve representative needs_intelligence continuity

Maps to representative selection (earliest fallback, then lexical token),
`since` retention across representative changes and the representative change
that writes no trail record (PRD t1.ob8.s4, SRD t1.ob8.gw SR-2.1, SR-5.1).

## Setup

As for the public case. One `claude` spawn `representative` in
`check_permission` holds three requests owned by its current launch and
interval, each with a fallback clock long past the 3600 s timeout: `Write`
with token `cccccccc-cccc-4ccc-cccc-cccccccccccc` at
2020-01-01T00:00:00.001Z, `Read` with token
`bbbbbbbb-bbbb-4bbb-bbbb-bbbbbbbbbbbb` at 2020-01-01T00:00:00.000Z and the
fixture's token and tool at 2020-01-01T00:00:00.000Z. The driver asserts the
tokens sort A < B < C.

## Steps

1. Run `status` until `observation_version` moves (at most 5 reads, exactly
   1). Read `status` again.
2. Set `pane_answer='outside'` on the fixture-token request with `sql.sh`.
   Run `get` until `observation_version` moves by exactly 1 (at most 5
   reads), then read `get` again.
3. Set `closed_at` on the `Read` request. Run `status` until
   `observation_version` moves by exactly 1 (at most 5 reads), then read
   `status` again and `observation_version`.
4. Read the trail records whose `instance_id` is `representative`.

## Pass criteria

- Step 1 row: state `needs_intelligence`, the fixture's token and tool
  (earliest fallback tied with `Read`, lowest token wins),
  `idle_screen_availability` `available`, `since` in the fixture's format at
  or after the case start, and exactly the status keys the public case
  lists. Call this `since` S.
- Step 2 row: `request_token` `bbbbbbbb-...`, `tool_name` `Read`, `since`
  equal to S, no `unchanged_minutes` and no `stuck_reason` member.
- Step 3 row: `request_token` `cccccccc-...`, `tool_name` `Write`, `since`
  equal to S, exactly the public case's status keys; the repeated read
  leaves `observation_version` unchanged.
- The raw `spawns.state` is `check_permission` throughout.
- The trail holds exactly one `ad.spawn.displayed_state_transition` record
  for the id, the entry: exactly the keys `instance_id`, `prior_state`,
  `new_state`, `event` and `ts`, `prior_state` `check_permission`,
  `new_state` `needs_intelligence`, `ts` equal to S. The two representative
  changes add none. No `ad.spawn.stuck_transition` record exists for the
  id, and no `ad.spawn.state_transition` record names `needs_intelligence`
  or `idle_screen`.
- The evidence line shows each step's token prefix, tool and
  `observation_version` (1, 2 and 3), the record count and, in place of S's
  run-time timestamp, the facts asserted about it (`>=start,kept=ts`: at or
  after the case start, kept by both representative changes, and the
  record's `ts`), so every passing run prints the same line.

set -euo pipefail
