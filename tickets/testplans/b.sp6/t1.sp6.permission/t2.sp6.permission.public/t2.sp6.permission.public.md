# All agents expose durable needs_intelligence through independent reads under the configured timeout

Maps to the all-agent public display and process-to-process continuation of
`needs_intelligence`, its `idle_screen_availability`, its trail record and
the `[state] needs_intelligence_timeout_seconds` key (PRD t1.ob8.s4, SRD
t1.ob8.gw SR-1.1, SR-1.2, SR-4.1, SR-5.1, SR-6.2).

## Setup

The DB-reset fixture gives a fresh store at the binary's current schema. The
driver checks the store has the renamed v14 columns and the columns it seeds
(`spawns.observation_version`, `display_observation`, `display_exit`,
`idle_screen_timeout_seconds`, `permission_epoch` and the request ownership
and clock columns); a binary without them prints `availability: unavailable`
and exits 77. It writes `[state] settle_ms = 0` and
`needs_intelligence_timeout_seconds = 3600` to `config.toml`, loads the
expected wire fields from
`/work/source/cmd/agent-director/testdata/display/needs_intelligence.json`,
and records the case start time. All SQL uses `/opt/driver/sql.sh`; no prior
case or wall-clock delay supplies evidence.

## Steps

1. For each of `claude`, `codex` and `cursor`, insert a `check_permission`
   spawn `public-<agent>` (relay on, session `ts-public-<agent>`, launch token
   `1111111111111111`, `permission_epoch` 7) and one request with the
   fixture's token and tool, owned by that launch and epoch, with
   `fallback_at` 2020-01-01 and basis `deadline`.
2. Confirm `spawns.display_observation` is still empty, so only a read can
   commit the entry.
3. Run `agent-director status --instance-id public-<agent>` until
   `spawns.observation_version` moves, at most 5 reads at the same state. It
   must move by exactly 1.
4. Run `status`, then `get` (a fresh process), for the same id. Read
   `observation_version` again, then the trail records whose `instance_id`
   is `public-<agent>`.
5. Run `agent-director list --state needs_intelligence --limit 3`.
6. Insert a `claude` spawn `public-recent` as in step 1, with one request
   whose `fallback_at` is 10 minutes before the case start. Run `status` 5
   times and read `observation_version` before and after.
7. Rewrite `config.toml` with `needs_intelligence_timeout_seconds = 60`. Run
   `status` until `observation_version` moves by exactly 1 (at most 5
   reads), then `status` again and the trail records of `public-recent`.

## Pass criteria

- Every `status` and `get` row has state `needs_intelligence`, the fixture's
  `request_token` and `tool_name`, `tmux_session_name` `ts-<id>`,
  `idle_screen_availability` `available` for Claude and Codex and
  `unavailable` for Cursor, and a `since` in the fixture's exact
  millisecond-UTC format whose time is at or after the case start (the
  committing read, not the 2020 fallback clock).
- Each `status` row's keys are exactly `context`, `family_state`,
  `idle_screen_availability`, `request_token`, `since`, `state`,
  `tmux_session_name` and `tool_name`. Each `get` row has no
  `unchanged_minutes` and no `stuck_reason` member.
- `get.since` equals `status.since`; `get.permission_requests` and
  `get.unproven_requests` each hold 1 request.
- `observation_version` is unchanged by the repeated `status` and `get`; the
  raw `spawns.state` is still `check_permission`.
- `list` returns exactly the 3 ids, each with state `needs_intelligence` and
  its agent's `idle_screen_availability`. Leaving out `ended_at`,
  `launch_started_at`, `liveness_note`, `liveness_unverified_since` and
  `parent_id`, each row's keys are exactly `agent`, `cwd`, `family_state`,
  `idle_screen_availability`, `instance_id`, `labels`, `last_seen_at`,
  `permission_requests`, `relay_mode`, `started_at`, `state`,
  `state_changed_at` and `tmux_session_name`.
- Under the 3600 s timeout every step 6 read shows `check_permission` and
  `observation_version` does not move (the default 30 s would show
  `needs_intelligence`); after step 7 `status` passes the same row checks as
  step 4 for `public-recent`.
- For each of the 4 ids the trail holds exactly one
  `ad.spawn.displayed_state_transition` record, whose keys are exactly
  `instance_id`, `prior_state`, `new_state`, `event` and `ts`, with
  `prior_state` `check_permission`, `new_state` `needs_intelligence` and `ts`
  equal to the row's `since`. No `ad.spawn.stuck_transition` record exists
  for the id, and no `ad.spawn.state_transition` record names
  `needs_intelligence` or `idle_screen`.
- The evidence line shows the token prefix, tool, list size, each agent's
  `observation_version`, the record count per id, the state shown under each
  timeout and, in place of any run-time timestamp, the facts asserted about
  each `since` (`>=start,get=status=ts`: at or after the case start, equal
  across `status` and `get`, and the record's `ts`), so every passing run
  prints the same line.
