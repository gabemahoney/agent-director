# Cursor reports no_screen_change unavailable, never pane-stuck, while its permission request still qualifies

Maps to Epic t1.sp6.rk acceptance 3: every row carries
`no_screen_change_availability`, Cursor's is `unavailable` and is no third
reason, and a Cursor permission request still reports `permission_unanswered`.

## Setup

The DB-reset fixture gives a fresh store at the binary's current schema. The
driver writes `[state] settle_ms = 0`, `no_screen_change_timeout_seconds = 60`
and `permission_unanswered_timeout_seconds = 30`. All SQL uses
`/opt/driver/sql.sh`.

## Steps

1. Insert a `working` Cursor row `cursor-quiet` with a 1-second override and
   a committed pane baseline unchanged since 2020-01-01 in its current
   permission epoch; run `status` and `get`.
2. Insert a `check_permission` Cursor row `cursor-asks` and one request with
   the shared permission fixture's token and tool, owned by its launch and
   epoch, its fallback clock started 2020-01-01; run `status` until it commits
   (exactly 1).
3. Insert an `ended` Codex row `codex-ended`; run `list`.

## Pass criteria

- Step 1: both reads show `working`, `no_screen_change_availability`
  `unavailable` and no `stuck_reason` or `unchanged_minutes`; the row's
  `stuck_version`, `stuck_observation` and baseline are unchanged (it was
  never sampled).
- Step 2: `status` shows the fixture's `stuck` / `permission_unanswered` and
  `request_token`, availability `unavailable` and no `unchanged_minutes`.
- Step 3: every listed row carries its availability: `codex-ended`
  `available`, both Cursor rows `unavailable`.
