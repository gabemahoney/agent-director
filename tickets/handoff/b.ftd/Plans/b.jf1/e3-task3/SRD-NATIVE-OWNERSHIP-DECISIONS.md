

### E3 Task3 native-operation ownership and process audit shutdown — coordinator

Adopted Engineer technical decisions, independent validation/review pending:

All cancelable bounded calls admit to one shared per-pool operation slot before spawning a worker, including before database/sql may open a physical connection. No job queue or goroutine is created for callers waiting for this slot. The slot remains held through actual callback and direct quarantine/disposal completion, even if the caller already returned. No unbounded worker per call, timeout, SQL statement or native blockage. Legacy no-context/default-wait calls keep the earlier synchronous and cleanup-lane path.

The original context still governs acquisition and every explicit SQL/cleanup call. A positive absolute deadline is never extended. Early cancellation requests SQL stop immediately, while the caller can observe a cooperative driver's actual result until the SAME original absolute deadline; this preserves ordinary setup I/O errors when returned in that interval. There is no extra grace period. At expiration the operation state is locked: a precommit abandonment prevents any later COMMIT; once COMMIT started, timeout is explicitly unconfirmed, never Busy/nothing written. SQL result publication precedes cleanup, so a confirmed COMMIT remains success if only cleanup outlives the context.

Zero-wait admission still uses1ms connGrab, and SQLite lock allowance remains zero. Uncontended connection initialization/SQL use the existing fixed1s immediate-work budget, intersected by the enclosing original context. A private context value separates zero-wait pool admission from that SQL initialization budget. It does not renew a positive expired deadline.

Local modernc.org/sqlite v1.34.0 inspection establishes a concrete context gap: Driver.Open/newConn has no context; applyQueryParams invokes DSN PRAGMAs with context.Background; statement cancellation uses cooperative interruptOnDone, and native step/finalize/Close may still block. The new sqliteConnector opens without DSN PRAGMAs, checks the actual context after native open and before each initialization statement, and initializes busy_timeout/foreign_keys with ExecContext before lending the connection. Expired opening closes/disposes the connection without starting initialization SQL. Foreign keys and configured busy timeout remain set on EVERY physical replacement connection. No WAL-setting pragma or schema change is added.

Result variables captured by a late worker must not be named return slots overwritten by an early error return. AckRelayDecision, DenyRelayTimeout and AckCursorDecision now use private locals and explicit zero outputs on error. RecordHookGone clones the variadic request-id input. Production Cursor callbacks capture their exact launch binding before dispatch, so later rotation cannot mutate the old operation's evidence. Existing synchronous c.check remains available to its existing internal callers/tests; no test-only source hook was introduced.

Process lifecycle: after CLI run returns, main gives the process trail singleton a separate fixed500ms teardown allowance within the already-documented1s CLI return reserve. It calls Writer.Close once, never emits a duplicate called event, never drains on Background, and explicitly diagnoses pending/failed shutdown. This budget is OUTSIDE the verb's original SQL/reporting context; the verb is not granted extra execution or retry time. api.Client.Close still owns only its store, and embedded API/MCP owners retain explicit process-lifetime trail ownership. Successful teardown means accepted events completed their worker fsync attempts; pending events remain memory-resident and may be lost at process exit. No crash-durability promise is added.
