# A fallen-back permission request keeps check_permission and live command authority

Maps to the report-only guarantee: what `send-keys`, `decide` and `pause` may
do follows the raw state, a refusal writes no trail record (PRD t1.ob8.s4,
SRD t1.ob8.gw SR-5.2, acceptance criterion 11 of Epic t1.sp6.6s), and the
request, fallen back since 2020, keeps its row `check_permission` across those
refusals (b.zpv). A later busy Codex pause ends its process and row keylessly
(b.y7g); Cursor pause remains refused.

## Setup

As for the public case, but per agent a relay-on spawn `guard-<agent>` with
one request (token `aaaaaaaa-aaaa-4aaa-aaaa-aaaaaaaaaaaa`, tool `Bash`) whose
fallback clock is already stored: `fallback_at` 2020-01-01, basis
`deadline`. Each is first read once with `status`. The Codex row records the
PID and start identity of a dedicated `sleep` child owned by the driver,
never the driver's own PID; the driver cleans up that child on failure.

## Steps

1. For each of `codex` and `cursor`, agents busy send does not cover, run
   `agent-director send-keys --instance-id guard-<agent> --text next`. (A
   covered Claude row holds the Message while the Dialog may be open and is
   paused keylessly instead: `busy-send-claude-wait-turn-2` and `-3`, Idea
   `b.kii`.)
2. Run `agent-director decide --instance-id guard-<agent> --request-token aaaaaaaa-aaaa-4aaa-aaaa-aaaaaaaaaaaa --decision allow --max-wait-ms 0`.
   A zero wait cannot wait for a store lock, so under load it may refuse
   `ErrStoreBusy`, recording nothing: rerun it, every 100 ms for at most
   10 s, only while that is its refusal. Any other outcome ends the retry.
3. For Cursor, run `agent-director pause --instance-id guard-cursor`.
4. Before pausing Codex, read the request's `decision`, `proven_gone_at` and `pane_answer` with
   `sql.sh`, then run `status` again and read the trail records whose
   `instance_id` is `guard-<agent>`.
5. Run `agent-director pause --instance-id guard-codex`. Check the owned
   child's process identity and read the stored raw state with `sql.sh`
   before any recovering CLI read. Read its trail again.

## Pass criteria

- The first and the second `status` each have state `check_permission`,
  `idle_screen_availability` `available` for Codex and
  `unavailable` for Cursor, exactly the keys `confirmations`, `context`,
  `failure_reason`, `family_state`, `idle_screen_availability`, `process_liveness` and
  `state`, with `failure_reason: null` (b.ivj), and exactly three `confirmations` records (`displayed_state`,
  `process_liveness`, `state`), each with the keys `checked_at`,
  `confirmed_at`, `reason`, `source` and `status`.
- Steps 1 and 2 each exit non-zero with a stderr JSON envelope whose
  `err_name` is `ErrRelayFallenBack` for both agents; Cursor's step 3 exits
  non-zero with `err_name` `ErrSpawnNotPausable`. A step 2 success, any other
  refusal, or `ErrStoreBusy` still answered after the 10 s retry fails the
  case.
- The request row is `decision` empty, `proven_gone_at` empty, `pane_answer`
  `none` (read as `||none`), and the raw `spawns.state` is still
  `check_permission` at step 4. Codex pause runs only after these assertions.
- Step 5 exits zero with `{}`; the driver's owned child is gone (absent,
  replaced by a different start identity, or exited in kernel state Z/X while
  awaiting Node's reap), and stored `spawns.state` is exactly `ended`.
- Per id the trail holds no `ad.spawn.displayed_state_transition` record, no
  `ad.spawn.stuck_transition` record, and no `ad.spawn.state_transition`
  record naming `needs_intelligence` or `idle_screen`.
- The evidence line shows each verb's observed result (`ended` for Codex
  pause and `ErrSpawnNotPausable` for Cursor pause), the untouched request
  facts checked before Codex pause, the state shown then and the record count.
