# needs-intelligence

Shell testplan for fallen-back permission requests, which never show the
`needs_intelligence` Displayed State (b.zpv): a known permission request keeps
its row `check_permission` however long it waits. The driver resets a
binary-derived store before each independent case and writes `[state]
needs_intelligence_timeout_seconds = 1`, the lowest value the key accepts, which
has no effect. No credentials, interactive agent or background worker is
needed, and no wall-clock wait supplies evidence: each case seeds requests
whose `confirm_by` passed in 2020, and the shipped binary does every
observation. The only wait is `guards`' bounded retry of its zero-wait
`decide` while that refuses `ErrStoreBusy` under load (every 100 ms, at most
10 s).

The cases cover, through public reads, refusals and the audit trail, every
agent's fallen-back request read as `check_permission` with no
`displayed_state`, listed by `--state check_permission`, its fallback clock
still established and persisted by a read, and the report-only command
guards. No read writes an `ad.spawn.displayed_state_transition` record to
`~/.config/agent-director/ad-trail.jsonl`; the DB reset leaves that file, so
each case reads only its own instance ids' records. A `needs_intelligence`
display an earlier release stored, its exit and settling stay unit tests.
Each case prints one compact JSON evidence line of observed values, with no
run-time timestamp, so every passing run prints the same line (a case on a
binary without the v14 columns prints `availability: unavailable` and exits
77, never a pass). The runnable driver is `test/driver/needs-intelligence.cjs`.
