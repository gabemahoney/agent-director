# interact-9: send-keys with keysym-text payload stays literal

Pins the bug fix for `b.btj`: a `text` payload containing a token that
exactly matches a tmux keysym (`Enter`, `Tab`, `BSpace`, …) must be sent
literally — `tmux send-keys -l <text>` — and the trailing submit must
remain a real Enter keystroke. Without `-l`, the first matching token
would fire as a real keysym event and submit the buffer prematurely (a
"Spawn-driving Claude composes a multi-token payload" scenario).

Revised by Epic 11 (`t1.h98.m6`, Task `t2.h98.m6.ki`; SR-3.4, SR-3.6,
SR-7.2, SR-20.9): the pane is read back with `read-pane`, which finds
the row's session only by its `@ad_owner` label and captures the
agent's pane by pane id. The session is seeded like kill-1
(`t2.75s.ks.3h`): the row has a launch token and records no socket,
server, pid or pane; the session carries the five-field label
`ad1 <token> <$N> id-i9 <store id>` and its pane `@ad_pane`
`<token> <%N>`, so `read-pane` finds the agent's pane through that
`@ad_pane` and writes nothing (`row_version` and `pane_id` unchanged).

## Setup

Per-case DB-reset. A `cat` pane echoes whatever the verb types. An EXIT
trap removes the session by its session id if the case fails part-way.

## Steps

1. Read this store's id from `store_meta` with `sqlite3`.
2. `tmux new-session -d -s cd-i9 -e AGENT_DIRECTOR_INSTANCE_ID=id-i9 --
   cat`, capturing `$N`, `%N` and the pane pid.
3. Seed a `spawns` row `id-i9` at state `waiting` with
   `tmux_session_name=cd-i9` and a 16-hex `launch_token`; read the token
   back with `sqlite3`.
4. Set the five-field `@ad_owner` label on `$N` and `@ad_pane`
   `<token> <%N>` on the pane; read the label back.
5. `agent-director send-keys --claude-instance-id id-i9 --text 'Enter the password'`.
6. Read the pane with `read-pane` (row `row_version` and `pane_id` read
   before and after); assert the literal line `Enter the password`
   appears intact (echoed back by cat).
7. Assert NO bare `the password` line appears on its own — a bare-rest
   line would prove the leading `Enter` fired as a keysym and submitted
   `Enter` alone, then `the password` was typed and echoed as a second
   line.

## Pass criteria

- The store id and token are 16 lowercase hex; the label read back has
  five fields and equals the one set.
- send-keys exit 0; read-pane exit 0.
- Pane contains the literal line `Enter the password`.
- Pane does NOT contain a bare `the password` line (i.e. with no
  preceding `Enter `) — the negative assertion that pins the bug.
- read-pane leaves `row_version` and `pane_id` unchanged.

## Script

```bash
set -euo pipefail
db="$HOME/.agent-director/state.db"
fail() { echo "FAIL: $*"; exit 1; }
sid=""
trap '[ -z "$sid" ] || tmux kill-session -t "$sid" 2>/dev/null || true' EXIT

store_id="$(sqlite3 "$db" "SELECT value FROM store_meta WHERE key = 'store_id';")"
[[ "$store_id" =~ ^[0-9a-f]{16}$ ]] || fail "store_meta store_id is not 16 lowercase hex: [$store_id]"

read -r sid pane pane_pid < <(tmux new-session -d -s cd-i9 -e AGENT_DIRECTOR_INSTANCE_ID=id-i9 \
    -P -F '#{session_id} #{pane_id} #{pane_pid}' -- cat)
[[ "$sid" =~ ^\$[0-9]+$ ]] || fail "new-session gave session id [$sid]"
[[ "$pane" =~ ^%[0-9]+$ ]] || fail "new-session gave pane id [$pane]"

seed_token="$(od -An -N8 -tx1 /dev/urandom | tr -dc '0-9a-f')"
sqlite3 "$db" \
  "INSERT INTO spawns (claude_instance_id, state, cwd, tmux_session_name, relay_mode, launch_token)
   VALUES ('id-i9', 'waiting', '/tmp', 'cd-i9', 'off', '$seed_token');"
token="$(sqlite3 "$db" "SELECT launch_token FROM spawns WHERE claude_instance_id = 'id-i9';")"
[[ "$token" =~ ^[0-9a-f]{16}$ ]] || fail "launch_token is not 16 lowercase hex: [$token]"

label="ad1 $token $sid id-i9 $store_id"
tmux set-option -t "$sid" @ad_owner "$label"
tmux set-option -p -t "$pane" @ad_pane "$token $pane"
got_label="$(tmux show-options -t "$sid" -v @ad_owner)"
[ "$got_label" = "$label" ] || fail "label read back [$got_label]; want [$label]"
read -r -a fields <<<"$got_label"
[ "${#fields[@]}" -eq 5 ] || fail "label has ${#fields[@]} fields; want 5: [$got_label]"

agent-director send-keys --claude-instance-id id-i9 --text 'Enter the password' >/dev/null || fail "send-keys exited non-zero"
sleep 0.2

row_q="SELECT row_version || '|' || COALESCE(pane_id, '') FROM spawns WHERE claude_instance_id = 'id-i9';"
before="$(sqlite3 "$db" "$row_q")"
rp="$(agent-director read-pane --claude-instance-id id-i9 --n-lines 100)" || fail "read-pane exited non-zero"
after="$(sqlite3 "$db" "$row_q")"
[ "$before" = "$after" ] || fail "read-pane changed the row: row_version|pane_id [$before] -> [$after]"

pane_text="$(jq -r '.pane' <<<"$rp")"
echo "$pane_text" | grep -qE '^Enter the password$' || fail "no literal 'Enter the password' line in pane $pane: [$pane_text]"
# Negative: a bare "the password" line on its own would mean the
# leading "Enter" fired as a keysym and the rest typed afterward.
n_bare="$(echo "$pane_text" | grep -cE '^the password$' || true)"
test "$n_bare" = "0" || fail "bare 'the password' line(s): $n_bare: [$pane_text]"
echo "interact-9 ok: keysym-text payload stayed literal; pane $pane read by id; row unchanged ($after)"
```
