spec/tla/hold36h/ provenance

What this is
  Bee b.36h's TLA+ model of the store's working hold as a read followed by
  a separate write, with the store lock (Hold36h.tla, built on b.omt's
  OmtHold). Write = "split" is the code before b.36h's fix: the UPDATE to
  working carries the gate only, so a relay request recorded between the
  hold's read and that UPDATE is overwritten with working. Write = "cond"
  is the fix: the UPDATE carries the hold's NOT EXISTS (holdsRowSQL), and a
  lost race is reported as held. With the model come its 16 cfgs, the
  scripts that wrote them and the job directories, the 16 scheduler job
  directories as submitted (less their jar, below), the job table, the job
  ids and the audited verdicts. Bee b.36h owns the model and its results.
  The files are vendored as the record of the model checking done before
  b.36h's product code.

Results
  All 16 jobs match job-README.md's expected table (verdicts.txt, audited
  2026-10-10). Every fix run is a complete PASS (cond_live3 2,655,041
  distinct states, cond_safe3 2,811,652); red_split and red_split_all fail
  WorkingTrue on today's write; ctl_split_nosub passes; every red run and
  probe fails on its target.

Not wired into make tla
  Nothing in the repo runs these files. `make tla` runs ci/suite.tsv only,
  and ci/run_ci.sh never reads hold36h/. To run a job again, copy
  spec/tla/tla2tools.jar into its job-<run>/ directory and submit that
  directory to the job scheduler.

Source
  Bee b.36h, directory tickets/Bugs/b.36h/ of the Apiary ticket tree
  (outside this repo). Copied byte for byte with rsync -a on 2026-10-10 and
  checked equal to the source with diff -r. Not copied: the bee's ticket
  file, its fix plan, and each job directory's tla2tools.jar. Every one of
  those 16 jars was checked byte-identical (cmp) to spec/tla/tla2tools.jar,
  SHA-256 32d64fbbc464559fc7192341b27b885fa4eb6b92d1648d2b49fb9cdcb7aacf81,
  so the repo keeps one copy. At copy time every job directory was also
  checked to hold exactly six files: tlcjob.sh equal to
  spec/tla/jobs/lib/tlcjob.sh, Hold36h.tla equal to tla/Hold36h.tla, its cfg
  equal to tla/cfg/<run>.cfg, a Dockerfile equal to every other job's, its
  runs file and the jar.

Layout (the bee folder's relative layout)
  tla/Hold36h.tla         the model
  tla/cfg/*.cfg           one cfg per scheduler job (16)
  tla/suite.tsv           run, expected verdict, what it shows
  tla/gencfg.py           wrote tla/cfg/ and tla/suite.tsv
  tla/mkjobs.sh           wrote the job directories
  tla/runlocal.sh         the capped (2 GB) local sanity runs
  job-<run>/              each job directory as submitted, less its jar
  job-README.md           the job table, with the expected verdicts and
                          the local sanity results
  job-ids.txt             the 16 scheduler job ids
  verdicts.txt            the audited JOB-VERDICT line of each job
