# Independent requests preserve representative episode continuity

Maps to representative selection (earliest fallback, then lexical token) and
`since` retention across representative changes (PRD t1.ob8.s4).

## Setup

As for the public case. One `claude` spawn `representative` in
`check_permission` holds three requests owned by its current launch and
interval, each with a fallback clock long past the timeout: `Write` with token
`cccccccc-cccc-4ccc-cccc-cccccccccccc` at 2020-01-01T00:00:00.001Z, `Read`
with token `bbbbbbbb-bbbb-4bbb-bbbb-bbbbbbbbbbbb` at 2020-01-01T00:00:00.000Z
and the fixture's token and tool at 2020-01-01T00:00:00.000Z. The driver asserts the
tokens sort A < B < C.

## Steps

1. Run `status` until `stuck_version` moves (at most 5 reads, exactly 1).
   Read `status` again.
2. Set `pane_answer='outside'` on the fixture-token request with `sql.sh`.
   Run `get` until `stuck_version` moves by exactly 1 (at most 5 reads), then
   read `get` again.
3. Set `closed_at` on the `Read` request. Run `status` until `stuck_version`
   moves by exactly 1 (at most 5 reads), then read `status` again and
   `stuck_version`.

## Pass criteria

- Step 1 row: the fixture's `state`, `stuck_reason`, token and tool (earliest
  fallback tied with `Read`, lowest token wins), `since` in the fixture's format at or after the
  case start, no `unchanged_minutes`. Call this `since` S.
- Step 2 row: `request_token` `bbbbbbbb-...`, `tool_name` `Read`, `since`
  equal to S.
- Step 3 row: `request_token` `cccccccc-...`, `tool_name` `Write`, `since`
  equal to S; the repeated read leaves `stuck_version` unchanged.
- The raw `spawns.state` is `check_permission` throughout.
- The evidence line shows each step's token prefix, tool and `stuck_version`
  (1, 2 and 3) and S.
