# spawn-2: UserPromptSubmit hook drives state to working

Maps to Epic 3 AC #2 (attaching to tmux and typing a prompt flips state
to working). The harness exercises the SRD §5.2 mapping directly via a
synthesized hook payload — no real Claude is needed for the state pin.
Epic 8 (`t1.h98.xw`, SR-20.9, SR-22.9): a hook moves the row only when
it comes from the row's own pane process, so each hook is typed into the
pane.

## Setup

Per-case DB-reset has wiped the DB. The spawn runs with
`PATH=/opt/driver/stand-in-claude:$PATH` prefixed to the `agent-director`
command (tmux finds `claude` on the launching process's PATH), so the pane
process is the stand-in claude's interactive bash, and
`/opt/driver/pane-hook.sh <id> '<payload>'` types each hook into that
pane with `tmux send-keys` (exiting with the hook's exit status). No hook
is piped from the case's own shell.

## Steps

1. `PATH=/opt/driver/stand-in-claude:$PATH agent-director spawn --cwd /tmp`
   → capture `claude_instance_id`.
2. Type a SessionStart hook into the pane → state should be `waiting`.
3. Type a `UserPromptSubmit` hook into the pane → state should be
   `working`.

## Pass criteria

- After step 2, `status` returns `waiting`.
- After step 3, `status` returns `working`.

## Script

```bash
set -euo pipefail
id="$(PATH="/opt/driver/stand-in-claude:$PATH" agent-director spawn --cwd /tmp | jq -r '.claude_instance_id')"
test -n "$id"
/opt/driver/pane-hook.sh "$id" '{"hook_event_name":"SessionStart","transcript_path":"/x/abc.jsonl"}'
state="$(agent-director status --claude-instance-id "$id" | jq -r '.state')"
test "$state" = "waiting"
/opt/driver/pane-hook.sh "$id" '{"hook_event_name":"UserPromptSubmit"}'
state="$(agent-director status --claude-instance-id "$id" | jq -r '.state')"
test "$state" = "working"
echo "spawn-2 ok: id=$id state=working"
```
